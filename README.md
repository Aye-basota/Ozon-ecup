# Ozon e-cup — Ценность пользователей поиска

## О проекте

По дневной истории активности пользователя в Поиске и Каталоге
(запросы, корзины, покупки) предсказываем суммарный GMV за следующие 30 дней.
Горизонт теста: **2026-02-14 .. 2026-03-15**, 250 000 пользователей.

## Метрика

**RMSLE** с `log1p`, отрицательные предсказания клипятся нулём.
Это обычный MSE в переменной `z = log1p(y)` — значит, L2-регрессия на `log1p(y)`
оптимизирует метрику точно, кастомный лосс не нужен.

## Валидация (единая для всех)

Out-of-time cutoff-схема, `src/validation.py`:

- на каждом cutoff `T` признаки строятся только по `event_date <= T`,
  таргет — сумма `gmv` в `(T, T+30]`;
- **панель валидации всегда 3-блочная** — это правило отбора, которым организатор
  собрал тестовые 250k («активен в каждом из трёх последних 30-дневных блоков»);
- **чистый коридор cutoff'ов 2025-04-03 .. 2025-10-16**: всё, что позже, отравлено
  (target-окно пересекает гарантированное окно активности панели);
- 4 фолда S1: `V ∈ {2025-09-04, 2025-09-18, 2025-10-02, 2025-10-16}`;
- рядом с RMSLE всегда смотреть `bias = mean log1p(y) − mean z`.

```
├── STATE.md             — текущее состояние, читать перед каждой задачей
├── AGENTS.md            — правила для ИИ-агентов
├── experiments/         — exp_NNN.md + log.csv (журнал всех прогонов)
├── research/            — EDA и стратегии
│   ├── eda_findings.md
│   ├── strategy_1.md          — план
│   └── strategy_1_results.md  — что из плана подтвердилось на данных
├── src/
│   ├── config.py        — seed, коридор cutoff'ов, глубина истории L, якорь уровня
│   ├── data.py          — единственная точка чтения train.parquet
│   ├── features.py      — build_features(T, L): панель, агрегаты, таргет
│   ├── validation.py    — RMSLE, фолды S1, кривая bias(gap)
│   ├── models.py        — direct / two-part / catboost на log1p(y)
│   ├── train.py         — раннер эксперимента (фолды -> OOF -> log.csv)
│   ├── predict.py       — инференс на тесте и сборка сабмита
│   ├── anchor.py        — якорная калибровка уровня + её бэктест
│   ├── seasonal.py      — dm(T), сезонная поправка
│   ├── drift.py         — bias как функция разрыва train->val
│   ├── tune.py          — кривая по раундам, сетка гиперпараметров
│   ├── adversarial.py   — adversarial AUC против тестового cutoff'а
│   ├── error_analysis.py— сегментный разбор ошибок между двумя OOF
│   └── smoke.py         — проверки корректности пайплайна
├── data/                — данные (не коммитим)
└── submissions/         — сабмиты (не коммитим)
```

## Быстрый старт

```bash
pip install -r requirements.txt
# положить train.parquet и sample_submit.csv в data/raw/

python -m src.smoke                      # проверки: панель 250k, якорь 2.2421, лукап
python -m src.features --L 180 --min-history 90   # прогреть кэш фичей (~2 c/cutoff)
python -m src.train --exp MY-EXP --L 180 --min-history 90 --train-blocks 1 --cutoffs all
python -m src.predict --exp S1-BEST ...  # сабмит
```

Точные команды воспроизведения `S1-BEST` — в `research/strategy_1_results.md`.

## Ветки

- `main` — только через PR.
- `team-a`, `team-b` — рабочие ветки команд; Strategy 1 — `team-a-strategy-1-impl`.

Правила:
- Раз в день подливаем `main` к себе в ветку.
- Фичи только **добавляются новыми колонками**, чужие не переписываем.

## Принципы

1. Единая валидация на всех — только `src/validation.py`.
2. Один пайплайн фичей `build_features(T, L)` для train/val/test.
3. Только out-of-time валидация; коридор чистых cutoff'ов соблюдать строго.
4. Один эксперимент = одно изменение = одна строка в `experiments/log.csv`.
5. Результат любого эксперимента записывается, даже провал.
6. Параметры постпроцессинга подбираются только на OOF, никогда на leaderboard.
