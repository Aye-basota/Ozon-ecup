## Гипотеза

`exp_027` показал: главная ось провала `SEQAVG3-MIX` на LB — глубина истории.
`exp_029` попробовал ввести край в обучение аугментацией **только канала `avail`** и
получил REJECT: OOD-режим ушёл, но польза длинной истории сжалась на 33–47 % —
инвариантность была куплена частичным игнорированием истории.

EXP-030 меняет не маску, а саму историю: во время обучения вход с вероятностью
`p = 0.5` обрезается до `D ~ U{90, 120, 150, 180, 220, 254, 289}` **реальных** дней.
Ожидание: энкодер научится читать префиксы разной длины, и переход к большей
глубине перестанет быть экстраполяцией.

## Что изменено относительно базы

Один флаг `--depth-aug 0.5` в сборке обучающего батча. Архитектура, target,
optimizer, число эпох, seed и порядок батчей — те же.

Ключевой инвариант приёма (тест `test_depth_sample_is_bitwise_the_production_depth_clip`):
`depth_sample = D` даёт **побитово тот же вход**, что боевой `--depth-clip D`.
Поведенческие каналы и `avail` режутся согласованно, календарные — нет, таргет
не участвует. Обрезка только ДОБАВЛЯЕТ позиции `avail = 0`, поэтому режим
`avail ≡ 1` остаётся непрожитым и политика теста остаётся `--depth-clip 289`.

## Корректность и анти-лукап

`python -m pytest src/test_seq.py -q` — **82 passed** (было 63). Отдельно проверено:

- вход curriculum побитово равен боевому `depth_clip` на всех глубинах сетки;
- режется только прошлое; хвост окна и календарные каналы не тронуты;
- глубина своя на каждый пример, а не общая на батч;
- при любой глубине число present-дней = число строк лога в `(T−D, T]` (анти-лукап);
- `avail` остаётся монотонной границей, число нулей только растёт;
- при `p = 0` вход побитово равен доаугментационному — BASE остаётся контролем;
- план эпохи у BASE и D3A совпадает (отдельный поток случайности);
- инференс не аугментируется: `depth_aug` на `predict` не влияет вовсе;
- curriculum и аугментация `avail` взаимоисключимы (assert).

Пофолдовый BASE переобучен в том же локальном eager-режиме, что и вариант.
Это обязательно: локальный режим систематически горячее исторического A10-прогона
`exp_025` (10-02: 1.75496 против 1.75352; 10-16: 1.74808 против 1.74704).

другое число из-за недетерминизма GPU, то есть было бы хуже, а не честнее.

### Где именно проигрывает 09-18

Дельта D3A−BASE по глубине на 09-18: +0.00147 (90), +0.00305 (120), +0.00384 (180),
+0.00384 (212), +0.00386 (240), +0.00355 (261) — практически **константа**.
На 10-16, наоборот, дельта РАСТЁТ с глубиной: −0.00055 (212) → −0.00117 (275) →
−0.00171 (289).

Значит проигрыш 09-18 — не глубинный эффект: механизм эксперимента и эта потеря
живут на разных осях. 09-18 — один из двух фолдов с отрицательным сдвигом
калибровки (−0.067 у BASE → −0.089 у D3A), то есть вариант там сильнее
перепрогнозирует, и одного глобального сдвига не хватает строкам без истории.

## Вердикт: `CONTINUE` (с оговоркой), 3 сида ОПРАВДАНЫ

Два пре-регистрированных гейта расходятся, и это надо назвать прямо.

- **Гейт EXP-030 из `PROBABLY_EXP.md` (собственный гейт эксперимента) — ПРОЙДЕН
  по обоим условиям:** RMSLE_cal на 10-16 улучшился на −0.00171 при требуемых
  ≥ −0.0005; cross-depth gain +77 не сжался (−0.00155 → −0.00368) при
  требуемых ≥ −0.0030. `availprobe` остался +0.0059, то есть проблема
  `avail ≡ 1` по-прежнему лечится обрезкой, а не curriculum'ом.
- **Сессионный гейт «≥3/4 фолдов» — НЕ ПРОЙДЕН: 2/4.** Условия «улучшение
  10-16» и «ΔwCV ≤ −0.0005» выполнены (−0.00077), консистентность — нет.

Почему всё же CONTINUE, а не REJECT:

1. ΔwCV = −0.00077 попадает в полосу «в разработку» (`exp_016` §6), а не в
   ухудшение; знак положительный на двух фолдах с суммарным весом 12 из 15.
2. Целевой механизм измерен напрямую и работает: 4/4 фолда по gain, 2.4× по
   crossdepth, исчезнувший внутренний оптимум. Это не выводной, а прямой замер
   на фиксированных весах, где меняется ровно одна величина.
3. При одном сиде ΔwCV в принципе неразрешима: seed std TCN по wCV = 0.00250,
   то есть в 3.2 раза больше наблюдённой дельты, а `Var(Δ)` = 0.0278 всего
   в 1.2 раза выше пары сидов на том же фолде (0.02270, `exp_029`). Один сид
   не может отличить «приём работает» от «удачный бросок» — ровно для этого
   и существует 3-сидовое подтверждение.

Почему не ACCEPT: 2/4 фолда, ΔwCV не берёт порог отправки −0.0020, суммарный
AUC плоский, и один фолд ухудшен на +0.00355 при неизвестной причине.
