# STRATEGY_01 — gap-axis validation

- **Дата:** 2026-08-12
- **Реализация:** `src/train.py --min-gap/--n-cutoffs`, `src/gapval.py`
- **Протокол:** seed 42, 4 fold S1, requested G=30/60/90/120
  (actual gap=35/63/91/126 из-за 7-дневной сетки)
- **Артефакты:** `artifacts/gap_axis_S1-GAPAXIS-FINAL.json` с ключами
  `<validation cutoff>|G<requested gap>`, рядом `*_curve.csv` и `*_selected.csv`

## Дизайн и capacity

Основная ось использует **k=5**: это заявленная в Data representation рабочая
конфигурация и единственное k, доступное на всех четырёх fold при G120. Строка
Variant A с `k=6` противоречит этой таблице и физически невозможна на fold 09-04;
использован выполнимый pre-registered `k=5`, а `k=11` проверен отдельно только
на 10-16, как предписано стратегией.

Для `E10/E03a/E02` снята curve 50/75/100/150/200/250/300, для дорогой `dist` —
50/100/150/200. Capacity выбирается отдельно для каждого `(probe,G)` по минимуму
wCV; точки 50/75 подтверждают, что выбранные 100–200 rounds не являются нижней
границей поиска. Выбранная таблица — [`gap_curve_selected.csv`](gap_curve_selected.csv),
direct-core — [`gap_curve_core.csv`](gap_curve_core.csv). У дорогого `dist` рассчитаны
решающие G30/G120 и G60; необязательный G90 остановлен при завершении этапа, поскольку
крайние точки уже сохраняли первое место `dist` и не могли изменить decision rule.

## Зарегистрированные проверки

### A — наклон bias: **не воспроизведён**

У `E10` weighted slope равен **+0.000543/day**, тогда как accept-band из `e12`
равен −0.0019…−0.0037/day. Все четыре пофолдовых slope положительны. Вывод не
является артефактом выбора capacity: на каждом фиксированном числе rounds 50–300
slope также положителен (+0.000474…+0.000604/day).

Контроль `k=11` на fold 10-16 тоже не даёт линейной зависимости: bias `E10` на
выбранной capacity равен −0.0442 / −0.0996 / −0.0490 / −0.0104. Подробности —
[`k11_latest_fold.csv`](k11_latest_fold.csv).

### B — страховка `E03a`: **относительный эффект есть, смены порядка нет**

На `k=5` дефицит `E03a−E10` монотонно сужается:

| actual gap | Δ wCV `E03a−E10` | fold wins `E03a` |
|---:|---:|---:|
| 35 | +0.009488 | 0/4 |
| 63 | +0.008224 | 0/4 |
| 91 | +0.007107 | 0/4 |
| 126 | +0.006268 | 0/4 |

Эффект существенно больше seed-noise и одинаков по знаку на всех fold, поэтому
дорогой avg3 здесь не меняет решение. На `k=11` результат тот же: +0.01017 →
+0.00790, но `E03a` не обгоняет `E10` ни в одной точке.

### C — f4: **pre-registered локальный контроль противоречив**

Production f4 удаляет пять test-train cutoff'ов после 2025-09-11. Для validation
10-16 они уже недопустимы: full/f4 дают одинаковые 24 даты при G30 и одинаковые
20 при G60. Локально удалить пять самых свежих *допустимых* дат можно (24→19 и
20→15), но это другая интервенция и не воспроизводит LB-факт f4. Детерминированный
audit записан в итоговом JSON; бессодержательное повторное обучение не запускалось.

## Gap effect и решение

У `E10` стресс-скор действительно ухудшается: **1.751415 (G35) → 1.756366
(G126), +0.004951**; std по fold при G126 = 0.01087 < kill-limit 0.02. То есть
старение train-выборки создаёт реальную трудность, но ось не воспроизводит
зарегистрированный механизм bias и не меняет содержательно порядок моделей.

## Решение: **REJECT**

Accept требовал одновременно A и (B или C): A провален, C неизмерим по построению,
B даёт только уменьшение дефицита без rank reversal. Дополнительно вывод зависит
от k, а значит gCV нельзя использовать как selection-критерий для 02C/04/09/10/12.
Конкретное правило после эксперимента: `Δ_gap = score(G126)-score(G35)` оставлять
только диагностикой; решения по shift-sensitive стратегиям принимать по обычным
wCV/fold gates и отдельным причинным stress-тестам, не по этому gCV.

Воспроизведение:

```bash
python -m src.gapval --run --probes e10 e03a e02 dist
python -m src.gapval --run --no-summary --probes e10 e03a --n-cutoffs 11 --val 2025-10-16
python -m src.gapval --summarize --out S1-GAPAXIS-FINAL
```
