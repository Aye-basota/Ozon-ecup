# FNL1 — EXP-038: future-funnel supervision, пилот на 2025-10-16

Сессия 2026-08-20. Одна машина, RTX 4060 Ti 8 ГБ, eager (`torch.compile` на этой
машине не работает — Windows без Triton, см. `ecup-seq-gpu-budget`).

## Что меряется

Даёт ли будущая активность воронки (`Search`, `Cart`) в окне `(T, T+h]` энкодеру
`SEQ-D3A` информацию, которой нет в purchase-супервизии. Четыре арки, один
энкодер, один порядок батчей, один бюджет:

| арка | вспомогательные головы | что изолирует |
|---|---|---|
| `BASE` | нет | свежий контроль того же кода |
| `BUYCTRL` | `buy30` | вторая голова БЕЗ нового источника информации |
| `CART` | `any_cart_7/14/30`, `log1p(to_cart_30)` | будущая корзина |
| `FUNNEL` | `CART` + `any_search_7/14/30`, `log1p(searches_30)` | корзина + поиск |

Главное сравнение — **`FUNNEL` против `BUYCTRL` при совпадающей `lambda`**, а не
против `BASE`. `BUYCTRL` играет ту же роль, что контроль `SELF` в `exp_024`:
разница с ним — это ровно новый источник, без эффекта multi-task регуляризации.
Второе сравнение — `CART` против `FUNNEL`: добавляет ли Search что-то сверх Cart.

## Очередь

`run.sh`, строго последовательно (два процесса с плотной панелью не помещаются в
свободную RAM). Порядок — по информативности, а не по симметрии: главная пара
считается первой, реплика `lambda = 0.1` последней.

| # | exp | арка | lambda |
|---|---|---|---|
| 1 | `FNL-BASE-L00-S42` | BASE | — |
| 2 | `FNL-FUNNEL-L30-S42` | FUNNEL | 0.3 |
| 3 | `FNL-BUYCTRL-L30-S42` | BUYCTRL | 0.3 |
| 4 | `FNL-CART-L30-S42` | CART | 0.3 |
| 5 | `FNL-FUNNEL-L10-S42` | FUNNEL | 0.1 |
| 6 | `FNL-BUYCTRL-L10-S42` | BUYCTRL | 0.1 |
| 7 | `FNL-CART-L10-S42` | CART | 0.1 |

Прогон, у которого OOF уже на диске, пропускается — очередь перезапускаема.
Фолд ~77 мин, вся очередь ~9 ч плюс ~1.3 ч на контроль шума.

## Контроль шума прогона (`run_ctrl.sh`)

Дельты арок меряются между РАЗНЫМИ ПРОЦЕССАМИ, а рецепт проекта держит
`cudnn.benchmark = True` + TF32 + bf16 и не включает
`use_deterministic_algorithms`. Внутри одного процесса всё детерминировано
побитово (`test_lambda_zero_is_bitwise_the_base_run`), а между процессами — нет:

| прогон | фолд 10-16, калибр. RMSLE |
|---|---|
| `SEQ-D3A-S42` (`exp_030`, та же машина, тот же сид, 4 эпохи) | 1.74637 |
| `FNL-BASE-L00-S42` (этот эксперимент, тот же рецепт) | **1.74713** |

Разница **+0.00076** при нулевом изменении постановки. Поэтому в очередь добавлен
`FNL-BASER2` — повтор BASE тем же сидом и тем же кодом. Новой информации в нём
нет по построению, и его дельта к `FNL-BASE` есть **цена самого прогона**: та же
роль, что у контроля `SELF` в `exp_024` и перемешанной `rho` в `exp_021`. Любая
дельта арки, не превосходящая её, результатом не считается.

## Инцидент с числом эпох

Первый запуск очереди полагался на `seq.DEFAULT_CFG`, где `epochs = 3`, тогда как
подтверждённый рецепт `SEQ-D3A` — 4 эпохи (`exp_030c`, `SEQ7/run_g1.sh` передаёт
`--epochs 4` явно). Прогон BASE на 3 эпохах остановлен и сохранён под тегом
`FNL-BASE-E3-L00-S42` (калибр. 1.74522, кривая 1.74671 → 1.74580 → 1.74522 —
на третьей эпохе всё ещё улучшается). Очередь перезапущена; теперь все ручки
рецепта проставлены в `run.sh` явно, а после каждого прогона стоит проверка, что
в логе есть «эпоха 4/4».

## Конфиг

`SEQ-D3A` без изменений: dilated causal TCN, hidden 64, blocks 8, kernel 3,
dropout 0.10, batch 1024, chunk 256, lr 3e-3 AdamW cosine, wd 1e-2, epochs 4,
warmup 300, bf16, 245 633 параметра энкодера, окно 365 дней, 17 каналов,
`--depth-aug 0.5` с сеткой `90 120 150 180 220 254 289`, train-панель 1-блочная,
val 3-блочная, 24 обучающих cutoff'а `2025-04-03..2025-09-11` (`T + 30 <= V`),
4 955 174 примера, 14 526 шагов. Сид 42.

Вспомогательная голова — один `Linear(192 -> M)` на том же pooled-векторе,
что читает главная, веса нулевые, bias — константный предсказатель
(+193 / +772 / +1544 параметра). Loss:

```text
L = MSE(z30) + lambda * s_z * mean_m( L_m / s_m ),   s_z = Var(z30) = 5.4899
```

`s_m` — потеря константного предсказателя головы (энтропия доли для бинарных,
дисперсия для регрессионных), поэтому нормированная aux-потеря стартует ровно с
1.0, а `lambda` читается как «во сколько раз вспомогательная задача дешевле
главной». Усреднение по головам, а не суммирование, уравнивает бюджет арок:
у BUYCTRL одна голова, у FUNNEL восемь.

## Гейт

```text
STRONG CONTINUE : FUNNEL - BASE <= -0.003  И  FUNNEL - BUYCTRL <= -0.001
                  И `rec_buy 15-60` не ухудшается
CONTINUE        : FUNNEL - BASE <= -0.0015 И явный выигрыш над BUYCTRL
                  или сильный AUC-gain в проблемных сегментах
REJECT          : |FUNNEL - BUYCTRL| <= 0.0005, либо aux-головы предсказываются
                  хорошо, а главный прогноз не улучшается
```

Разрешающая способность: пофолдовая парная sd этого энкодера на этом фолде по
сидам = **0.00038** (`exp_030c`), то есть полоса REJECT `±0.0003…0.0005` лежит
на пределе одного прогона. Отрицательный вывод держится не на одном числе
RMSLE, а на согласии двух `lambda` плюс таблице `aux_auc.csv`.
