# SEQ7 — сессия 2026-08-19: EXP-030 на 3 сидах (2× A10) + пилот EXP-032 (локальная 4060 Ti)

Один координатор, три карты, жёсткая аренда 5 часов. Здесь зафиксировано, как
распределялись вычисления и почему именно так, чтобы числа читались корректно.

уезжает снимок рабочего дерева (`src/`), они работают как вычислители, а не как
авторы. `STATE.md`, `experiments/log.csv` и общие артефакты пишутся один раз и
только локально, после сбора результатов. `git reset/clean` не выполнялись.

## Бенчмарк, по которому строилось расписание

`python3 -m src.seq bench --n-cutoffs 3 --iters 15 --compile` на GPU-A:

```
сборка батча (1 поток)  13.1 мс -> 78 069 примеров/с
[  eager] forward 53.2 мс | forward+backward+шаг 129.9 мс | GPU-доля 100%
[compile] forward 21.1 мс | forward+backward+шаг  65.2 мс | GPU-доля 100%
```

Отсюда решение включить `--compile`: шаг вдвое дешевле, и вместо двух фолдов на
карту в 5 часов помещаются все четыре парно. По факту обучения (с учётом
пайплайна данных) вышло 452 с/эпоху на GPU-A и 339 с/эпоху на GPU-B при 4 842
шагах — то есть 93 и 70 мс/шаг.

**Компиляция включена у ОБОИХ членов каждой пары.** Это принципиально: контраст
`D3A − BASE` остаётся внутрисредовым, а абсолютные уровни между машинами не
сравниваются. `exp_030` уже намерил, что локальный eager систематически горячее
A10 на 0.0010–0.0015, и это ровно та причина, по которой единицей анализа взята
пофолдовая парная дельта, а не уровень.

## Расписание: план и факт (UTC, аренда с ~13:00, жёсткий предел 17:58)

Планировалось по бенчмарку 65.2 мс/шаг; по факту пайплайн данных добавил
поверх, и вышло 93 мс/шаг на GPU-A и 70 на GPU-B. Порядок пар это выдержал.

| пара | GPU-A, сид 43 (факт) | GPU-B, сид 44 (факт) |
|---|---|---|
| старт | 13:05 | 13:18 (задержка: torch cu128 + typing_extensions) |
| 10-16 | 13:05 → 14:06 | 13:18 → 14:05 |
| 10-02 | 14:06 → 15:03 | 14:05 → 14:49 |
| 09-04 / 09-18 | 15:03 → 15:44 | 14:49 → 15:44 |
| 09-18 / 09-04 | 15:44 → ~16:33 | 15:44 → 16:00 |
| диагностика | ~16:33 → ~17:00 | 16:01 → 16:16 |

Обе карты уложились в аренду с запасом около часа. Порядок пар — по убыванию
веса фолда в `wCV` (8:4:1:2), внутри пары сначала D3A, затем BASE. Фолд полезен
только целой парой, поэтому аренда резалась по границам пар: если бы время
кончилось, потерялась бы последняя пара целиком, а не половина каждой. У сида 43
последним поставлен 09-18 — он уже был посчитан локально (`exp_030b`), то есть
это была наименее ценная пара из четырёх.

Диагностику запускал watcher сразу после последней пары, без простоя GPU, и
внутри она тоже упорядочена по ценности: `crossdepth` (+77 дней = точный аналог
теста, главное утверждение `exp_030`) → `depth` на гейтовом 10-16 → `availprobe`
→ `depth` на остальных фолдах.

Локальная RTX 4060 Ti в это время закрыла EXP-032: заказанный пилот на 10-16,
а затем — поскольку карта иначе простаивала бы — остальные три фолда и развёртку
по трём сидам головы.

## Проблемы среды, которые стоили времени

* На GPU-B `pip install torch==2.11.0` ставит колесо **cu130**, а драйвер 570.211
  даёт CUDA 12.8 → `torch.cuda.is_available() == False`. Лечится явным
  `--index-url .../cu128` и версией `2.11.0+cu128`; без `--force`/деинсталляции
  pip считает требование удовлетворённым и ничего не меняет.
* После этого `torch.compile` падал на `Too few arguments for CSE`: системный
  `typing_extensions` 4.10 из Debian против 4.15 у рабочей машины. Лечится
  `pip install --ignore-installed typing_extensions==4.15.0`.
* Панель на GPU-B собирается за 19 с (`python3 -m src.seq build`), на GPU-A уже
  была с прошлой аренды. Переносить 3.7 ГБ `data/processed` по сети не нужно —
  достаточно `data/raw/train.parquet` (180 МБ).
