# STRATEGY_02 — Variant B: dense temporal grid при равном объёме

- **Дата:** 2026-08-12
- **Эксперимент:** `experiments/exp_022_dense_temporal_grid.md`
- **Гипотеза:** больше temporal states содержит дополнительную информацию само по
  себе, даже если общее число train-строк не растёт.
- **Итог:** **FAIL** — плотность ухудшила score, activity AUC и оба заранее
  выбранных проблемных сегмента.

## Контролируемый дизайн

В обоих плечах неизменны 227 признаков `S1-E10`, 30-дневный GMV target, четыре
fold S1, 3-блочная validation-панель, `direct` LightGBM и все параметры из
`config.py`. Новых признаков нет; каждая train-дата удовлетворяет `T+30≤V`.

| | baseline | dense B |
|---|---|---|
| cutoff step | 7 дней | 3 дня |
| train panel | `train_blocks=1` | `train_blocks=1` |
| пользователи на cutoff | все | `(user_id·2654435761) mod 1000 < 422` |
| hash-доля | 100% | 42.2%, независимо от target |
| temporal states на fold | 18 / 20 / 22 / 24 | 43 / 47 / 52 / 57 |
| train rows | 3.668 / 4.092 / 4.521 / 4.955 млн | 3.704 / 4.062 / 4.516 / 4.976 млн |

Отклонение объёма dense от baseline: **+0.97% / −0.72% / −0.11% / +0.41%**,
то есть каждый fold попадает в зарегистрированный допуск ±1%. Hash-решение
одинаково для пользователя на всех cutoff: dense-плечо содержит больше состояний
каждой выбранной траектории, а не случайные одиночные строки.

Фактическая dense grid отсчитана назад от `2025-10-16` с шагом 3. Для train она
равна диапазонам `2025-04-01..2025-08-05`, `..2025-08-17`, `..2025-09-01`,
`..2025-09-16` на четырёх fold соответственно. Полные списки всех дат и аудит
объёма: [`variant_B_cutoff_grid.csv`](variant_B_cutoff_grid.csv).

## Capacity curve

После вывода `STRATEGY_05` сравнение на фиксированных 600 или 300 trees было бы
некорректным. На seed `config.SEED=42` для обоих плеч снята одна и та же prefix
curve; остальные параметры модели не менялись.

| rounds | baseline wCV | dense wCV | dense − baseline |
|---:|---:|---:|---:|
| 150 | 1.751168 | 1.752239 | +0.001071 |
| 200 | **1.751030** | 1.752339 | +0.001308 |
| 250 | 1.751043 | 1.752547 | +0.001504 |
| 300 | 1.751076 | 1.752884 | +0.001807 |
| 450 | 1.751407 | 1.753776 | +0.002368 |

Правило `STRATEGY_05` — минимум на последнем fold, затем wCV — выбирает **300
rounds для baseline и 200 для dense**. У dense глобальный минимум wCV находится
на 150, но он также хуже capacity-matched baseline на всех четырёх fold; выбор
150 вместо 200 не меняет решение. Полная таблица:
[`variant_B_capacity_curve.csv`](variant_B_capacity_curve.csv).

## Главный результат

| fold | baseline, 300 | dense, 200 | Δ dense − baseline |
|---|---:|---:|---:|
| 2025-09-04 | 1.771059 | 1.771716 | +0.000657 |
| 2025-09-18 | 1.764799 | 1.765820 | +0.001021 |
| 2025-10-02 | 1.752425 | 1.754145 | +0.001719 |
| 2025-10-16 | 1.744473 | 1.745643 | +0.001170 |
| **wCV 1:2:4:8** | **1.751076** | **1.752339** | **+0.001263** |

Dense проигрывает **0/4 fold**, включая последний. Эффект примерно `9σ` разницы
двух независимых seed-score (`σ_diff≈0.00014` из `STRATEGY_05`) и имеет один знак
на всех fold, поэтому avg3 не запускался: условие «подтвердить несколькими seeds,
если эффект сравним с seed noise» не выполнено. Таблица фактически доступных
seed-артефактов и решение об остановке:
[`variant_B_seed_robustness.csv`](variant_B_seed_robustness.csv).

## Activity и проблемные сегменты

Метрики посчитаны после того же пофолдового оптимального log-сдвига, без
посегментной калибровки.

| сегмент | метрика | baseline | dense | Δ |
|---|---|---:|---:|---:|
| все | AUC(y>0), weighted | 0.843101 | 0.842684 | **−0.000416** |
| `rec_buy 15–60` | RMSLE | 1.949951 | 1.951508 | **+0.001557** |
| | AUC(y>0) | 0.719118 | 0.717910 | **−0.001208** |
| 2–15 purchase days (`w180_days_buy`) | RMSLE | 1.952905 | 1.954416 | **+0.001512** |
| | AUC(y>0) | 0.717503 | 0.716568 | **−0.000935** |

Ни общего activity signal, ни локального улучшения в областях, которые держат
основную RMSLE-ошибку, нет. Пофолдовые AUC/RMSLE и полные строки сегментов:
[`variant_B_fold_metrics.csv`](variant_B_fold_metrics.csv),
[`variant_B_segment_metrics.csv`](variant_B_segment_metrics.csv).

Дополнительная диагностика показывает реальное изменение модели, а не её полное
совпадение с baseline: `Var(z_dense−z_base)=0.01229`, corr остатков `0.99801`.
Но изменение направлено в худшую сторону и превышает seed-floor `Var=0.00712`.

## Verdict для heavy temporal models: **FAIL**

При фиксированном бюджете строк перенос ёмкости выборки с числа различных
пользователей на число temporal states не добавляет информации: wCV хуже на 4/4,
AUC активности ниже, оба целевых сегмента хуже. Тезис о **dense supervision как
самостоятельном источнике signal** существенно ослаблен; `STRATEGY_10 HDN/TCN`
не получает подтверждения от этого gate и **не запускается автоматически**.

Это не доказательство невозможности sequence-модели вообще: HDN/TCN может дать
другой inductive bias. Результат уже и точнее — при сопоставимом train volume
сама плотность cutoff-разметки не компенсирует потерю разнообразия пользователей.
