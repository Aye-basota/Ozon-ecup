# Strategy NN-1 — HDN: Horizon Distribution Network

> **Источник преимущества:** не новые признаки и не новая архитектура ради архитектуры,
> а **смена объекта обучения**. Вместо «регрессия скаляра `z = log1p(y)` на 6.07 млн
> материализованных строк» — «условное **распределение** горизонта, предсказанное
> в **каждый день** чистого коридора одним причинным проходом по дневной панели».
>
> Ветка-предок: `team-a-strategy-1-impl` (S1-BEST, LB 1.6512803).
> Все числа ниже помечены источником: `R*` — уже есть в репозитории,
> `N*` — измерено при подготовке этого документа (протоколы воспроизведения — §11).

## 1. Наблюдения, из которых выросла стратегия

### 1.1 Что уже закрыто и больше не даёт прироста

| что | измерение | вывод |
|-----|-----------|-------|
| **Уровень прогноза** | `L* = 2.3293` восстановлен по трём сабмитам, совпадение модели `MSE(L)=C+(L*−L)²` с LB до 7-го знака; зазор основного сабмита до оптимума **0.0000285** (`R1`, `strategy_1_results.md` §5.4) | δ как источник прироста **закрыт** |

AUC экстенсива 0.84565 → 0.84598 (`N6`) | табличные признаки **насыщены**; ср. `R4`: сырые недельные лаги дали −0.00024 |

**Из этой таблицы следует главное для выбора стратегии:** прирост больше не лежит
ни в постпроцессинге, ни в новых агрегатах, ни в более полном представлении
*долгосрочного профиля* пользователя. Всё это выбрано.

### 1.2 Где на самом деле лежит остаток ошибки

Разложение OOF `S1-BEST` (770 616 строк, 4 фолда, `N1`, `N3`):

```
MSE = 3.0930                RMSLE = 1.75871
Var(z_true) = 5.514         std(z_true) = 2.348
std(z_pred) = 1.531         corr = 0.6635        R² = 0.439

оракул «знаем 1[y>0]»                        RMSLE 1.04957     (MSE 1.102)
оракул «знаем n = число покупательных дней»  RMSLE 0.73518     (MSE 0.540)
```

| компонента остаточной дисперсии | доля |
|---------------------------------|------|
| **экстенсив** `p(1−p)·m²` — «купит ли вообще» | **74.6 %** |
| интенсив `p·σ²` — «на сколько купит» | 25.4 % |

`Var(z \| n, n>0) ≈ 0.875`. То есть **82.5 % текущей ошибки — это незнание числа
покупательных дней в горизонте**, а не незнание сумм.

AUC текущей модели по `1[y>0]`: **0.8417** (скор регрессии) / **0.8457**
(отдельный бинарный LightGBM на тех же признаках) (`N4`).

Это же подтверждается сверху: топ-1 признак по SHAP — `w180_days_buy` (14.6 %),
топ-2 — `w180_orders` (7.4 %), денежные агрегаты идут заметно ниже (`R14`).
**Задача частотная, а модель обучается на денежном скаляре.**

### 1.3 Счётный процесс сверхдисперсен — и это не только нулевая инфляция

`N5`, фолд 2025-10-16, `n` = число дней с `gmv>0` в `(T, T+30]`:

```
глобально:  mean 2.005  var 7.435  var/mean = 3.708      (Пуассон = 1.0)
            P(n=0) факт 0.3871 против exp(−λ) = 0.1347   (разрыв +0.2525)

внутри страт по w180_days_buy:
   0      var/mean 2.02   P(0) 0.858 против Пуассона 0.808
   1      var/mean 1.73   P(0) 0.699 против 0.626
   2–3    var/mean 1.75   P(0) 0.567 против 0.475
   4–7    var/mean 1.75   P(0) 0.392 против 0.287
   8–15   var/mean 1.81   P(0) 0.201 против 0.111
   16+    var/mean 2.63   P(0) 0.050 против 0.007
```

Сверхдисперсия сохраняется **условно**, в каждой страте, и у самых активных
она максимальна (2.63) — значит это не нулевая инфляция, а настоящая
пачечность (burstiness). Отсюда практический вывод: параметрическое семейство
(Пуассон, даже с hurdle, как в S2 — `R9`) **мисспецифицировано**. Нужна
**непараметрическая дискретная голова**.

### 1.4 Прямая проверка: голова распределения бьёт L2 на тех же данных

Это ключевой замер (`N12`). Фолд 2025-10-16, train — 3 cutoff'а (644 087 строк),
**те же 236 признаков**, тот же LightGBM, отличается **только голова**:

| постановка | RMSLE | AUC(`1[y>0]`) | mean z |
|------------|-------|---------------|--------|
| **A.** L2 на `z` (как сейчас), 600 раундов | 1.75002 | 0.84207 | 2.7054 |
| **B.** softmax по **16 бинам `z`** (бин 0 = ровно ноль), 250 раундов, `ẑ = Σ p_k m_k` | **1.74606** | **0.84664** | 2.6952 |
| **C.** softmax по числу покупательных дней `n∈{0..8+}`, `ẑ = Σ p_n E[z\|n]` | 1.76198 | 0.84678 | 2.7227 |
| **C2.** то же × таблица «чек» (5 бакетов `w180_lgmv_mean`) | 1.75066 | — | 2.7161 |

```
B  против A:  −0.00396 RMSLE, +0.00457 AUC       (и это при 250 раундах против 600)
блендА+B  w=0.75 → 1.74557    corr остатков 0.9955
блендА+C  w=0.25 → 1.74806    corr остатков 0.9850   ← минимальная из всех измеренных
блендА+C2 w=0.45 → 1.74723    corr остатков 0.9929
тройная A/B/C2 0.2/0.6/0.2 → 1.74540   (−0.00462 к A)
```

**Масштаб:** вся программа Strategy 1 от `S1-B0` до `S1-BEST` дала −0.00993 по CV
(`R2`). Одна смена головы даёт **−0.0040**, тройная композиция голов — **−0.0046**,
то есть ~45 % всей проделанной работы, из одного изменения, на бустинге.

Причина ровно та, что в §1.2: оптимум метрики — это `E[z|x]`, **среднее условного
распределения**. Оценивать это среднее напрямую L2-регрессией по таргету с точечной
массой 0.39 в нуле и тяжёлым хвостом — статистически неэффективно. Оценить
распределение (кросс-энтропия — строго правильное scoring rule, градиенты
ограничены и хорошо обусловлены) и потом взять его среднее — оценка с меньшей
дисперсией. Для нейросети этот аргумент **сильнее**, чем для бустинга: у GBM
и так кусочно-постоянные листья, а у сети L2 по тяжёлохвостому таргету —
известный источник нестабильных градиентов.

### 1.5 Плотность супервизии: сколько её реально доступно

`N9`, панель 2025-10-16, корреляция таргетов при разных сдвигах cutoff'а:

```
сдвиг  0 дн : 1.0000      сдвиг 30 дн : 0.5335   ← окна НЕ пересекаются
сдвиг  7 дн : 0.8685      сдвиг 60 дн : 0.4980
сдвиг 14 дн : 0.7542
```

Соседние cutoff'ы (шаг 7) коррелируют 0.87 — но не 1.0. Плотная сетка уже дала
GBM −0.0070 (`R3`, S1-E02), это **самый крупный одиночный выигрыш всей Strategy 1**.
Сеть с причинным энкодером получает эти позиции **бесплатно**: один проход по
409-дневному ряду даёт корректное состояние `h_{i,t}` для *каждого* дня `t`.

```
GBM сейчас:  29 cutoff'ов × ~209k = 6.07 млн размеченных строк
HDN:        ~195 легальных дневных позиций × ~200k = ~39 млн размеченных примеров
            за ту же одну эпоху, без материализации 39 млн × 236 матрицы (38 ГБ)
```

Плюс к этому в каждой позиции доступны **дополнительные метки того же горизонта**:
`n`, `1[y>0]`, суммы за 7/14/60 дней, 30 дневных индикаторов покупки. Это ещё
×5…×30 к плотности сигнала.

### 1.6 Данные позволяют держать всё на одной GPU

`N7`:

```
строк на пользователя за 409 дней: p50=102, p75=178, p90=254, p99=356, max=409
плотная панель 250 000 × 409 дней × 7 каналов = 1.43 ГБ в fp16
```

Весь датасет соревнования помещается в память RTX 4060 Ti целиком. Эпоха —
минуты, а не часы. Это снимает главный аргумент против нейросетей в хакатоне
(«не успеем») и объясняет, почему этого почти никто не сделает: все считают,
что 30.6 млн строк — это «много».

### 1.7 Чего в данных нет (закрытые направления)

* **`gmv` не повторяется**: среди 4.74 млн ненулевых значений повторов нет вообще
  (`N8`). Значит нет словаря цен, нет прокси товара, нет общих объектов между
  пользователями → **GNN и любые cross-user модели построить не из чего**
  (это же подтверждает провал `EXP-SIM`: LB +0.01694).
* **Персонального random effect нет** (`N10`) → user-embedding'и, mixed effects,
  self-training по пользователям — мимо.
* **Внутригоризонтный хазард почти плоский**: `P(покупка в день d)` = 0.060…0.079
  по 30 дням, отношение «первые 5 дней / последние 5 дней» = 0.918 (`N11`).
  Значит подневный декодер горизонта — **слабый рычаг**, регуляризатор, а не
  источник преимущества. Продавать его как ядро стратегии нельзя.

## 2. Главная гипотеза

> **Текущая модель упирается не в признаки и не в объём данных, а в две вещи,
> которые бустинг изменить не может: (а) она оценивает скаляр вместо распределения,
> (б) она видит один размеченный пример на (пользователь, cutoff).
> Причинная сеть по дневной панели с дискретной головой распределения снимает оба
> ограничения одновременно, и это единственный оставшийся нетривиальный рычаг.**

Формально: метрика — MSE по `z`, оптимум `ẑ_i = E[z_i | x_i]`. Раскладываем через
счётный процесс горизонта:

```
E[z | x] = Σ_{n≥0} P(n | x) · E[z | n, x]
```

`P(n | x)` — сверхдисперсное дискретное распределение (§1.3), `E[z | n, x]` —
гладкая, почти одномерная функция от `n` и «типичного чека» (`Var(z|n,n>0)=0.875`).
Сеть учит обе компоненты явно, каждую своей — правильно обусловленной — функцией
потерь, и агрегирует их точно.

Три подгипотезы, каждая проверяется отдельным экспериментом (§7):

| # | подгипотеза | опора | статус |
|---|-------------|-------|--------|
| H1 | голова распределения бьёт L2 на одном и том же входе | `N12`: −0.0040 на бустинге | **подтверждена вне сети** |
| H2 | подневная супервизия (все ~195 позиций) снижает дисперсию оценки сильнее, чем шаг 7 | `R3` (+0.0070 от 3→29 cutoff'ов), `N9` (corr 0.87 ≠ 1.0) | гипотеза |
| H3 | инвариантность к глубине истории лечится **аугментацией**, а не усечением (`R7`: L=180 стоит +0.010) и не нормировкой (`R8`: adv AUC 1.0) | `R6` (adv AUC 0.993), `N15` (платформа ×1.72) | гипотеза |

## 3. Архитектура и представление входа

### 3.1 Вход: плотная дневная панель

Тензор `X ∈ R^{B × D × C}`, `D = 400` дней (колонка 0 = день `T`, растёт в прошлое),
`C = 11` каналов. Обоснование `D`: усечение до 180 стоит **+0.010**, до 90 —
**+0.031** (`R7`), а `w365_days_buy`/`w365_orders` дают 12.1 %/10.5 % gain (`R14`).
Рецептивное поле обязано покрывать ≥365 дней.

| # | канал | преобразование | почему |
|---|-------|----------------|--------|
| 1 | `present` | 1, если строка существует | «нет строки» ≠ «строка из нулей» |
| 2 | `presence_only` | строка есть, все счётчики нули | `R11`: до **+0.75** к `m_y` при контроле на прочее |
| 3 | `log1p(searches)` | | |
| 4 | `cat` | бинарный | единственная не-производная бинарная колонка (`R12`) |
| 5 | `log1p(to_cart)` | | |
| 6 | `log1p(to_ord)` | | |
| 7 | `log1p(gmv)` | | основной сигнал |
| 8 | `gmv_cat / (gmv+ε)` | доля каталога | |
| 9 | `cart_open` | `to_cart>0 & to_ord=0` | состояние воронки, не выражается агрегатом |
| 10–11 | `sin/cos(dow)` | | эффект слабый (0.955–1.033, `N15`), но бесплатный |

**Не включать** `has_*` и `search` — точные производные (`R12`), только разбавляют
вход.

Незаполненные дни — нули во всех каналах при `present = 0`. Это единственное место,
где заполнение нулями допустимо: канал `present` сохраняет различие состояний.

### 3.2 Энкодер: причинная дилатированная свёртка (TCN)

```
вход  (B, 11, 400)
stem  Conv1d(11 → 128, k=1)
7 блоков:  dilation 1,2,4,8,16,32,64;  kernel 5;  causal padding
           каждый блок: DepthwiseConv → GLU → Conv1d(1x1) → LayerNorm → residual
рецептивное поле  1 + 4·(1+2+4+8+16+32+64) = 509 дней  ✓ > 409
выход (B, 128, 400) — состояние h_{i,t} для КАЖДОГО дня t, строго причинное
```

**Почему TCN, а не RNN и не трансформер (в этой стратегии):**

* причинность + параллельность по всем 400 позициям — иначе трюк из §1.5 стоит
  ×400 по времени;
* `N6` показал, что топ-признаками стали **экспоненциальные ядра** `sh_ewm60_gmv`,
  `sh_ewm150_gmv` (83 % gain ушло новым признакам, при том что метрика не сдвинулась) —
  сигнал по времени **гладкий и убывающий**, а не «найди конкретный день в прошлом».
  Для гладкого затухания свёртка — правильный и самый дешёвый индуктивный bias.
  Content-based retrieval (то, ради чего нужен attention) здесь пока не подтверждён —
  это гипотеза Strategy NN-2, и её надо проверять отдельно, а не смешивать.

**Инициализация как явное обобщение текущих признаков.** Первый блок инициализируем
так, чтобы часть каналов на старте вычисляла ровно `w7/w14/w30/w60/w90/w180`-суммы
и EWMA с `τ ∈ {7,21,60,150}`. Сеть стартует не хуже текущего признакового базиса
и учится отклоняться от него. Это дёшево и убирает «нейросеть не догнала руками
сделанные фичи» как класс отказа.

### 3.3 Статический вход и явная глубина истории

К `h_{i,t}` конкатенируется:

* `depth_t = (t − 2025-01-01) / 409` — **явная** доступная глубина истории;
* `log1p(tenure_t)/log1p(depth_t)` — доля прожитой истории;
* макро-состояние платформы на `t`, нормированное: `log(buyers_30d(t) / buyers_180d(t))`,
  `log(gmv_30d(t) / gmv_180d(t))`. Обоснование `N15`: платформа между окном
  признаков теста и его YoY-аналогом выросла в **1.72 раза**; уровень таргета по
  коридору дрейфует 2.12 → 2.44 (`N16`). Абсолютные макро-величины экстраполировать
  нельзя, **отношения** — стационарны и переносятся.

**Аугментация глубины истории (H3).** С вероятностью 0.5 при обучении обрезаем
историю случайной глубиной `D' ~ U{90, 400}` (зануляем всё старше `D'` и ставим
`depth = D'`). Это заставляет сеть быть корректной при любой глубине, а не
переучиваться на «в обучении максимум 289 дней, на тесте 409» — механизм, который
дал adversarial AUC 0.993 (`R6`). В отличие от усечения до `L=180` (стоит +0.010,
`R7`) сигнал длинного окна **не теряется**; в отличие от нормировки (`R8`) не
создаётся cutoff-специфичного квантования.

### 3.4 Голова: факторизованное дискретное распределение

```
h_{i,t} (128) ──► MLP(256) ──┬── p_n     = softmax по n ∈ {0,1,…,14,15+}      (16)
                             ├── p_v     = softmax по 12 бинам log-чека        (12)
                             └── p_z     = softmax по 24 бинам z (бин 0 = ноль) (24)

ẑ_count = Σ_n p_n · Σ_v p_v · m(n, v)      m — таблица E[z | n, бин чека], с train
ẑ_bins  = Σ_k p_z(k) · c_k                 c_k — центроид бина, с train
ẑ       = w·ẑ_bins + (1−w)·ẑ_count         w подбирается на OOF
```

Бины `z`: бин 0 — **ровно** `z=0` (39 % массы), остальные 23 — квантили `z|z>0`.
Мягкие метки HL-Gauss (гауссова размазка метки по соседним бинам, σ = 0.75 ширины
бина) для положительной части; для нуля — жёсткая метка. Мягкие метки убирают
дискретизационное смещение и стабилизируют обучение.

Обоснование факторизации: `N12` — обе головы работают, но по-разному
(`corr` остатков A↔B = 0.9955, A↔C = **0.9850**, минимум из всех измеренных
на этих данных, включая структурную модель S2 с 0.9937 — `R9`).
Их композиция даёт больше каждой по отдельности (1.74540 против 1.74606/1.75066).

## 4. Loss и стратегия обучения

### 4.1 Функция потерь

```
L = 1.00 · CE(p_z,  бин(z_30))                   главная
  + 0.50 · CE(p_n,  n_30)                        счёт (74.6 % остаточной дисперсии)
  + 0.30 · CE(p_v,  бин(средний лог-чек))        только по n>0
  + 0.20 · BCE(1 − p_z[0], 1[y_30>0])            экстенсив явно
  + 0.15 · Σ_{h∈{7,14,60}} CE(p_z^h, бин(z_h))   мультигоризонт
  + 0.05 · Σ_{d=1..30} BCE(hazard_d, 1[покупка в день d])   регуляризатор
  + 0.10 · MSE(ẑ, z_30)                          выравнивает среднее с метрикой
```

Комментарии, каждый — из замера:

* веса 1.00/0.50/0.30 — прямое следствие `N3` (74.6 % / 25.4 %);
* мультигоризонт оправдан `N9`: 7-дневный таргет коррелирует с 30-дневным 0.87,
  но не 1.0, а шума в нём меньше на единицу времени; 60-дневный даёт 0.50 —
  почти независимую задачу;
* подневный hazard — **вес 0.05, не больше**: `N11` показал, что внутри горизонта
  почти нет структуры (0.060…0.079). Это регуляризатор энкодера, а не источник
  прироста. Если поднять вес — сеть потратит ёмкость на неинформативную задачу;
* `MSE(ẑ, z)` с малым весом обязателен: CE оптимизирует правдоподобие бинов,
  а нам нужно среднее. Малый MSE-член выправляет остаточное смещение
  дискретизации без разрушения обусловленности.

### 4.2 Плотная позиционная супервизия

```
для фолда с валидацией V:
    легальные позиции t:  2025-04-01 ≤ t ≤ CORRIDOR_END,  t + 30 ≤ V
    маска панели:         пользователь активен в (t−30, t]  (1-блочная, как S1-E01)
    всё остальное — mask=0, градиент не течёт
```

Правило `t + 30 ≤ V` — ровно `src/validation.py:get_folds`, ни строчки послабления.
Правило `t ≤ 2025-10-16` — коридор из `config.py`: любая позиция позже отравлена
правилом панели (`R3`).

Одна эпоха: 250k пользователей × ~195 позиций ≈ 39–48 млн размеченных примеров.
При batch = 512 пользователей это ~490 шагов на эпоху. 15–25 эпох.

### 4.3 Self-supervised предобучение — использование выброшенных 120 дней

Супервизия обязана выбросить `2025-10-17 .. 2026-02-13` — это **120 дней = 29 %
календаря, и именно самая похожая на тест его часть**. Но данные там легальны
(всё ≤ 2026-02-13), запрещено только использовать их как *таргет*.

Предобучение (2–3 эпохи, все 250k × 409 дней, включая отравленное окно и окно
признаков теста):

```
задача 1  masked day modelling: маскируем 15 % дней, восстанавливаем
          (present, buy?, бин log-gmv, бин searches) — двунаправленно
задача 2  next-event: предсказать Δt до следующего активного дня и его тип
          (это ровно точечный процесс = экстенсив, 74.6 % остатка)
```

Далее — причинный fine-tune с головами §3.4. Ожидаемый эффект двойной:
(1) обычный transfer, (2) **доменная адаптация**: энкодер видит режим ноября-2025 —
февраля-2026, в котором предстоит предсказывать, тогда как GBM обучен исключительно
на режиме апреля-октября 2025 (`R6`: adversarial AUC 0.993; `N15`: платформа ×1.72).

**Контроль честности:** после предобучения обязательно замерить adversarial AUC
эмбеддингов `h_{i,T}` «валидационный cutoff против тестового» (`src/adversarial.py`).
Цель < 0.80. Если 0.99 — предобучение не решило задачу, о которой заявлено.

### 4.4 Регуляризация и инференс

* dropout 0.1 внутри блоков, weight decay 0.01, AdamW, `lr 3e-4` с косинусом,
  warmup 500 шагов, `bf16`;
* усреднение по **5 сидам в лог-пространстве** (не в сыром GMV — неравенство
  Йенсена, `src/blend.py`);
* SWA/EMA весов — дешёвая замена части сидов;
* на инференсе `depth = 409`, аугментация выключена.

## 5. Валидация

**Протокол репозитория, без изменений.** `src/validation.py` и `src/config.py`
не трогаются (`AGENTS.md`).

```
фолды S1     V ∈ {2025-09-04, 2025-09-18, 2025-10-02, 2025-10-16}
панель val   ВСЕГДА 3-блочная (правило организатора)
позиции train  t + 30 ≤ V,  t ≤ 2025-10-16,  панель 1-блочная
метрики      RMSLE, bias = mean log1p(y) − mean z, RMSLE после оптимального сдвига
OOF          сохранять в формате artifacts/oof_<EXP>.npz (user_id, cutoff, z, y),
             чтобы src/blend.py работал без правок
```

### 5.1 Дополнительные обязательные проверки (специфичные для сети)

| проверка | как | порог |
|----------|-----|-------|
| **лукап по времени** | обучить с `D=400`, затем занулить всё `> t` вручную и сравнить `h_{i,t}` побитово | максимум \|разница\| = 0 |
| **лукап по позициям** | предсказание в позиции `t` не должно меняться при изменении данных в `(t, t+30]` | ровно 0 |
| **отравленные позиции** | доля позиций с `t > 2025-10-16` в обучении | ровно 0 |
| **разнообразие** | `Var(z_HDN − z_S1BEST)` на OOF | ≥ **0.10** (см. §8) |
| **adversarial AUC** | `h_{i,V}` против `h_{i,TEST}` | < 0.80 после SSL |
| **уровень** | `mean(log1p(pred))` на тесте после δ | ровно 2.3293 |

### 5.2 Чего валидация НЕ покажет

`R10`: LB-дельта соотносится с OOF-дельтой примерно как **1.13–1.20×**
(EXP-MIN: OOF +0.01349 → LB +0.01614; EXP-SIM: OOF +0.01494 → LB +0.01694;
S2: CV +0.00945 → LB +0.01065). Это надёжное отображение **для однородных
изменений модели**. Но:

* разрыв train→test = 120 дней локально недостижим (максимум 35 дней на фолдах);
* эффект SSL-предобучения на тестовом окне на локальных фолдах **систематически
  недооценивается** — ровно как якорная калибровка, которая локально давала
  +0.00017 (то есть вредила), а на LB стоила **+0.0076** (`R1`).

Поэтому по adversarial AUC и по величине bias(gap) решения принимать **наравне**
с CV, а не «после».

## 7. Приоритетные эксперименты

Порядок жёсткий: каждый следующий имеет смысл только если предыдущий прошёл.

### E-NN1.0 — плотная панель и «нулевая» сеть (4 ч)

* **Гипотеза:** датапайп корректен, лукапа нет.
* **Реализация:** собрать тензор `250k × 400 × 11` fp16; линейная голова поверх
  фиксированных box-ядер (`w7…w180`) — то есть буквально воспроизвести текущие
  агрегаты как свёртку. Обучить на фолде 2025-10-16.
* **Ожидание:** RMSLE в диапазоне 1.76–1.80 (не хуже «только недельные» = 1.79011,
  `R4`).
* **Стоп-условие:** оба теста лукапа из §5.1 обязаны дать ровно 0.
* **Ценность:** без этого все дальнейшие числа недостоверны.

### E-NN1.1 — TCN + голова распределения, один фолд (1 день) ⟵ **начинать здесь после E-NN1.0**

* **Гипотеза:** H1 переносится с бустинга на сеть.
* **Реализация:** §3.2 + §3.4, супервизия только на 29 сетевых cutoff'ах
  (шаг 7, как у GBM) — чтобы изолировать эффект **головы и архитектуры** от
  эффекта плотности.
* **Три числа, ради которых всё делается:**
  `RMSLE`, `AUC(1[y>0])`, `Var(z_HDN − z_S1BEST)`.
* **Решение:** продолжать при `RMSLE ≤ 1.77` **и** `Var(Δ) ≥ 0.10`.
  При `RMSLE > 1.79` — баг или архитектура, не тюнить, а искать ошибку.

### E-NN1.2 — плотность супервизии (0.5 дня)

* **Гипотеза:** H2. Позиции каждый день против шага 7.
* **Реализация:** тот же прогон, меняется только маска позиций (29 → ~195).
* **Метрика:** ΔRMSLE и, главное, **фолд-std** (при снижении дисперсии оценки он
  обязан упасть; у EXP-MIN падение std не спасло — но там падала и информация).
* **Решение:** оставить, если ΔRMSLE ≤ −0.002 хотя бы на 3 фолдах из 4.
  Если 0 — H2 опровергнута, и это важный результат: значит соседние cutoff'ы
  избыточны, и Strategy NN-2 надо строить без ставки на плотность.

### E-NN1.3 — абляция головы (0.5 дня)

* Голова L2 против `p_z` против `p_z + p_n` при прочем равном.
* **Ожидание:** воспроизвести знак и порядок `N12` (−0.004).
* **Решение:** если L2-голова не хуже — вся §1.4 не переносится на сеть,
  стратегия сворачивается до «ещё один член ансамбля».

### E-NN1.4 — аугментация глубины истории (0.5 дня)

* **Гипотеза:** H3.
* **Метрики:** CV **и** adversarial AUC эмбеддингов против теста.
* **Решение:** оставить, если adv AUC < 0.85 при `ΔCV ≥ −0.001`
  (то есть робастность не куплена ценой качества).

### E-NN1.5 — SSL-предобучение на всех 409 днях (1.5 дня)

* **Гипотеза:** 120 выброшенных дней + доменная адаптация.
* **Абляции:** (a) без SSL; (b) SSL только на коридоре; (c) SSL на всей истории.
* **Решение:** принимать (c) над (b), только если adv AUC падает **и** CV не растёт.
  Прирост на CV здесь ожидается малый — основной эффект должен проявиться на LB
  (аналогия с калибровкой уровня: локально +0.00017, на LB +0.0076, `R1`).

### E-NN1.6 — мультигоризонт и сиды (0.5 дня)

* Веса `{7,14,60}` в лоссе; 5 сидов, усреднение в лог-пространстве.

### E-NN1.7 — интеграция в ансамбль (0.5 дня)

* `python -m src.blend --exps S1-E10 S1-E02 S1-E03a HDN --step 0.05`
* **Решение:** принять, если вес HDN ≥ 0.15 **и** выигрыш ≥ 0.003 на ≥3 фолдах.

**Дешёвая параллельная проверка (не требует сети, 3 ч).** Обучить текущий GBM
на 6 млн строк, **выбранных из 197 cutoff'ов (шаг 1)** вместо 29 (шаг 7), при
одинаковом числе строк. Это изолирует «разнообразие cutoff'ов» от «объёма данных»
и заранее подтверждает или убивает H2 без единой строчки на torch.

## 8. Как понять, что стратегия работает, и когда бросать

### 8.1 Критерии успеха (по возрастанию требовательности)

| уровень | критерий | что означает |
|---------|----------|--------------|
| 0 | RMSLE < 1.79011 (`R4`, «только недельные» GBM) | сеть вообще учится |
| 1 | RMSLE ≤ 1.77 на фолде 2025-10-16 | архитектура рабочая |
| 2 | `Var(z_HDN − z_S1BEST) ≥ 0.10` | **есть разнообразие** |
| 3 | AUC(`1[y>0]`) ≥ 0.850 | атакована доминирующая компонента |
| 4 | вес в бленде ≥ 0.15 и выигрыш ≥ 0.003 на ≥3 фолдах | стратегия окупилась |
| 5 | одиночный калиброванный OOF < 1.75716 | сеть обогнала S1-BEST |

Уровень 5 **не является условием успеха**. Реалистичный сценарий — уровни 2–4.

### 8.2 Порог разнообразия — откуда 0.10

`N14`: расхождение внутри текущего семейства GBM микроскопическое.

```
Var(z_S1-E10 − z_S1-E02)  = 0.0245      corr(pred) 0.9949
Var(z_S1-E10 − z_S1-E03a) = 0.0443      corr(pred) 0.9908
Var(z_S1-E10 − z_S1-B0)   = 0.0507      corr(pred) 0.9899
```

При MSE = 3.093 всё семейство S1 — это **одна точка** в пространстве функций
(расхождение ≈ 1.6 % от MSE). Структурная S2, построенная как принципиально
другая модель, всё равно дала corr остатков 0.9937 и вес в бленде 0.025 (`R9`).
Порог `Var(Δ) ≥ 0.10` означает «расходимся вдвое сильнее, чем самые далёкие
две GBM-модели» — ниже этого ансамбль математически не окупит работу.

### 8.3 Критерии немедленного отказа

1. E-NN1.0 не проходит тесты лукапа → останавливаться и чинить, никаких метрик.
2. E-NN1.1: `RMSLE > 1.79` после честного подбора lr/эпох → архитектурная ошибка.
3. E-NN1.3: голова распределения не лучше L2 → главный тезис не переносится,
   стратегия сворачивается до «член ансамбля с весом ~0.1», дальше не вкладываться.
4. `Var(Δ) < 0.10` при паритете → отбрасывать (см. §8.2).
5. Любой прогон, где CV улучшается, а `mean(log1p(pred))` на тесте уходит из
   коридора 2.28–2.41 при δ = 0 — признак того, что модель поймала артефакт.

### 8.4 Ловушки, уже оплаченные командой

* **Не принимать решения по разнице < 0.01 на public LB** (50k, σ ≈ 0.005–0.007).
* **Не выбирать конфигурацию по фолд-std**: `EXP-MIN` имел меньший std и стабильную
  importance — и проиграл **+0.01614 на LB**.
* **Не путать низкую корреляцию с полезной декорреляцией**: `EXP-SIM` имел
  низкую Pearson-корреляцию и проиграл **+0.01694**. Мерить надо `Var(Δ)` при
  **паритете качества**, а не корреляцию у слабой модели.

## 9. Объединение с существующими моделями

Никакой новой инфраструктуры не требуется — сеть встраивается как ещё один
`exp_id` в уже работающий конвейер:

```
1. HDN сохраняет OOF в artifacts/oof_HDN.npz  (user_id, cutoff, z, y) —
   формат src/tracking.py, порядок строк совпадает с фолдами S1
2. python -m src.blend --exps S1-E10 S1-E02 S1-E03a HDN --step 0.05
   → веса и corr остатков, всё на OOF, никогда на LB
3. HDN сохраняет предсказание на тесте в artifacts/ztest_HDN.npy + uid_HDN.npy
4. python -m src.submit --z S1-NORM S1-UNC S1-CAP HDN --weights ... --level 2.3293
```

Уровень фиксирован: **`--level 2.3293`**, это измеренная константа, а не параметр
(`R1`). Смешивать **только в лог-пространстве** — в сыром GMV смесь смещает
уровень вверх по Йенсену (`src/submit.py`).

Три способа объединения, по возрастанию амбиций:

| способ | что делает | ожидание |
|--------|-----------|----------|
| **линейный бленд в `z`** | текущий механизм | основной сценарий |
| **бленд распределений** | усреднять `p_z` HDN с бинированным распределением, восстановленным из GBM-квантилей, и брать среднее уже у смеси | +0.001…+0.002 сверх линейного, если головы согласованы |
| **дистилляция** | обучить HDN дополнительно на мягкой цели `ẑ_S1BEST` (KD-член в лоссе с весом 0.1) | стабилизирует сеть на старте, но **снижает разнообразие** — использовать только если §8.2 провален и надо спасать хотя бы паритет |

**Порядок разговора с ансамблем важен:** сначала мерить `Var(Δ)` (§8.2),
и только потом подбирать веса. Если `Var(Δ)` мал, подбор весов даст
красивый in-sample выигрыш, который не перенесётся — ровно как у EXP-SIM.

## 10. Почему это может улучшить leaderboard

1. **Единственный оставшийся большой рычаг.** Уровень закрыт (`R1`), 1D- и
   сегментная калибровка закрыты (`N2`), ручные признаки насыщены (`N6`),
   персистентный профиль пользователя вычерпан (`N10`). Из непроверенного остаётся
   ровно две вещи: **параметризация выхода** и **плотность супервизии**. Обе —
   нейросетевые по природе.

2. **Первая уже измерена и работает.** −0.0040 RMSLE и +0.0046 AUC от одной
   смены головы на бустинге (`N12`), −0.0046 у композиции голов. При переносе
   1.13–1.20× (`R10`) это **−0.0045…−0.0055 на LB** только от головы, ещё до сети.
   Для сравнения: весь путь `S1-B0 → S1-BEST` стоил −0.0099 CV.

3. **Атакуется именно доминирующая компонента.** 74.6 % остаточной дисперсии —
   экстенсив (`N3`), а голова распределения улучшила именно AUC экстенсива, обойдя
   даже специально обученный бинарный классификатор (0.84664 против 0.84565, `N12`/`N6`).

4. **Ансамблевый резерв не выбран.** Всё семейство S1 расходится на `Var(Δ)=0.05`
   при MSE 3.09 (`N14`) — ансамбль насыщен. Модель другого класса с другим лоссом
   и другим входом — единственный способ его расширить.

5. **Робастность к сдвигу train→test — единственный неизмеренный риск.**
   Разрыв 120 дней локально недостижим (`R`, риски `strategy_1_results.md` §7),
   adversarial AUC 0.993 (`R6`), платформа выросла ×1.72 (`N15`). Аугментация
   глубины (§3.3) и SSL на тестовом окне (§4.3) — прямые ответы, и оба недоступны
   бустингу. История уже показала, что такие правки **дают на LB кратно больше,
   чем на CV** (калибровка уровня: +0.00017 локально, +0.0076 на LB).

6. **Этого почти никто не сделает.** Порог входа — не архитектура (TCN тривиален),
   а три вещи, которые надо было *измерить*, чтобы вообще додуматься:
   что задача частотная, а не денежная; что данные помещаются на одну GPU целиком;
   и что коридор чистых cutoff'ов даёт ~195 позиций подневной супервизии,
   а не 3 «свежих» cutoff'а. Типовое решение хакатона — GBM на агрегатах по окнам,
   обученный на 1–3 ближайших cutoff'ах; оно даже не подходит к этим рычагам.

**Честная оценка эффекта.** Одиночная HDN, скорее всего, окажется в диапазоне
1.750–1.765 CV, то есть **около или чуть хуже S1-BEST**. Основной вклад —
через ансамбль и через робастность: суммарно **−0.005 … −0.015 на LB**,
с вероятностью успеха ~60 % на уровнях 2–4 из §8.1. Это не «×2», и продавать
это как прорыв нельзя — но при закрытом уровне и насыщенных признаках это
крупнейший из оставшихся честных резервов.

## 11. Воспроизведение измерений `N*`

Все `N*` получены на текущей ветке поверх существующего кэша фичей.
Ключевой замер `N12` (§1.4) воспроизводится так:

```python
# фолд 2025-10-16, train — 2025-08-07 / 08-28 / 09-11, панель train 1-блочная,
# val 3-блочная, признаки — features_cached(T, None) без изменений
import numpy as np, lightgbm as lgb
from sklearn.metrics import roc_auc_score
P = dict(learning_rate=.05, num_leaves=127, min_data_in_leaf=200, feature_fraction=.7,
         bagging_fraction=.8, bagging_freq=1, lambda_l2=5., verbose=-1, seed=42,
         num_threads=12, max_bin=63, force_row_wise=True)

# A: как сейчас
zA = lgb.train(dict(P, objective="regression"), lgb.Dataset(Xtr, ztr), 600).predict(Xv)

# B: голова распределения
qs   = np.quantile(ztr[ztr > 0], np.linspace(0, 1, 16)[1:-1])
edg  = np.concatenate([[1e-9], qs])
ltr, K = np.searchsorted(edg, ztr, "right"), None
K    = int(ltr.max()) + 1
cent = np.array([ztr[ltr == k].mean() for k in range(K)])
Pb   = lgb.train(dict(P, objective="multiclass", num_class=K),
                 lgb.Dataset(Xtr, ltr), 250).predict(Xv)
zB   = Pb @ cent            # ЭТО и есть E[z|x]
# -> RMSLE 1.74606 против 1.75002 у A;  AUC 0.84664 против 0.84207
```

**Уточнение по AUC (перепроверено 2026-08-11 реализацией `src/models.py`).**
У головы распределения два разных читающих вектора, и `0.84664` — это **не** AUC
по `zB`. Воспроизведение того же протокола даёт:

```
A: RMSLE 1.75012  AUC(zA)      0.84194        (эталон 1.75002 / 0.84207)
B: RMSLE 1.74558  AUC(zB)      0.84368
                  AUC(1 - p0)  0.84689        (эталон 0.84664)
```

То есть экстенсивный сигнал головы надо читать вероятностью нуля `1 - p_0`,
а `zB` как ранжирующий признак «купит ли вообще» слабее, потому что подмешивает
интенсив. Для метрики это неважно (RMSLE считается по `zB` и воспроизводится),
но для HDN важно: **классификационная голова сети должна читаться через `p_0`,
а сравнение с бинарным классификатором (0.84565) корректно только в этом виде.**

Остальные протоколы:

| метка | что меряет | как |
|-------|-----------|-----|
| `N1`–`N3` | разложение OOF, оракулы, потолок калибровки | `artifacts/oof_S1-E{10,02,03a}.npz`, смесь 0.45/0.45/0.10 |
| `N5` | сверхдисперсия счёта по стратам | панель 2025-10-16 × `w180_days_buy` |
| `N6` | 164 признака формы | плотная панель 182 дня → EWMA/серии/dow/gap/26 недель |
| `N9` | корреляция таргетов между cutoff'ами | одна панель, 5 сдвигов |
| `N10` | персистентность остатка | pivot OOF по (user_id × cutoff), пары с непересекающимися окнами |
| `N12` | голова распределения | код выше |
| `N14` | расхождение GBM-вариантов | `Var(z_A − z_B)` на общем OOF |
