# E-Cup 2026 Search — прогноз GMV на 30 дней

## Задача

Построить модель, которая для каждого пользователя предсказывает **суммарный GMV (Gross Merchandise Value)** в Поиске и Каталоге за следующие 30 дней.

### Горизонт прогноза

- Исторические данные: **2025-01-01 — 2026-02-13**
- Период прогноза: **2026-02-14 — 2026-03-15**
- Длина горизонта: **30 дней**

## Данные

- Около **30+ млн** обезличенных дневных записей.
- **250 000 пользователей**.
- Одна строка соответствует агрегированной активности пользователя за один день.
- В данных присутствует статистика по:
  - покупкам;
  - добавлениям в корзину;
  - поисковым запросам;
  - стоимости заказов / GMV;
  - другим агрегированным признакам пользовательской активности.

### Важная особенность

Дневные временные ряды **разреженные**: дни без активности могут отсутствовать в исходных данных.

Не следует без необходимости полностью достраивать все пропущенные дни нулевыми строками, так как это может увеличить размер датасета примерно до **100 млн строк**.

## Target

Для каждого `user_id` необходимо предсказать:

\[
y_i = \text{суммарный GMV пользователя } i \text{ за следующие 30 дней}
\]

Предсказание модели обозначим как:

\[
\hat{y}_i
\]

При расчёте метрики отрицательные предсказания принудительно заменяются на `0`:

\[
\hat{y}_i^{+} = \max(0, \hat{y}_i)
\]

Поэтому на этапе формирования submission рекомендуется явно применять:

```python
prediction = max(0.0, prediction)
```

## Метрика

Используется **RMSLE** с `log1p`:

\[
RMSLE =
\sqrt{
\frac{1}{n}
\sum_{i=1}^{n}
\left(
\log(1+y_i) -
\log(1+\hat{y}_i^{+})
\right)^2
}
\]

где:

- `n` — число пользователей;
- `y_i` — истинный суммарный GMV пользователя за целевые 30 дней;
- `ŷ_i` — предсказанный GMV;
- `ŷ_i⁺ = max(0, ŷ_i)`.

### Практическое следствие

RMSLE измеряет ошибку в логарифмическом масштабе, поэтому:

- большие абсолютные ошибки у пользователей с высоким GMV штрафуются мягче, чем при RMSE;
- важна точность относительного масштаба прогноза;
- особенно опасны сильные завышения для пользователей с низким или нулевым GMV;
- полезно рассматривать обучение таргета в пространстве `log1p(y)`.

## Формат submission

Необходимо сформировать CSV-файл с предсказаниями для **всех 250 000 пользователей**.

Структура:

```csv
user_id,predict
2,0.0
7,486.96535
918481,31.039128
```

Требования:

- `user_id` — идентификатор пользователя;
- `predict` — предсказанный суммарный GMV за период `2026-02-14 — 2026-03-15`;
- одна строка на каждого пользователя;
- отрицательных предсказаний быть не должно.

## Leaderboard

Разделение пользователей:

- **Public:** 20% = 50 000 пользователей;
- **Private:** 80% = 200 000 пользователей.

Основной риск — переоптимизация под public leaderboard, поэтому локальная валидация должна максимально имитировать реальный 30-дневный forecasting horizon.

## Рекомендуемая схема локальной валидации

Для проверки модели использовать временной split:

1. Выбрать историческую дату отсечения `T`.
2. Построить признаки только по данным `<= T`.
3. Рассчитать target как суммарный GMV на интервале `(T, T + 30 дней]`.
4. Повторить для нескольких дат отсечения.
5. Считать RMSLE по пользователям.

Важно избегать leakage: ни один признак не должен использовать данные из будущего относительно даты отсечения.

## Возможные подходы

Базовые варианты:

- табличный ML:
  - CatBoost;
  - LightGBM;
  - XGBoost;
- агрегаты по временным окнам;
- time-series признаки;
- модели частоты и денежной ценности покупок;
- BTYD-подходы;
- sequence / transformer-модели по дневной активности.

Для сильного baseline разумно начать с табличной модели на пользовательских агрегатах за несколько временных окон и обучать её на `log1p(target)`.

## Минимальный baseline feature set

Для каждого пользователя можно собрать признаки по окнам, например:

- последние 7 дней;
- последние 14 дней;
- последние 30 дней;
- последние 60 дней;
- последние 90 дней;
- последние 180 дней;
- весь доступный период.

Типы признаков:

- суммарный GMV;
- число заказов;
- число дней с покупками;
- число активных дней;
- число поисковых запросов;
- число добавлений в корзину;
- средний чек;
- медианный чек;
- максимум GMV за день;
- средний GMV на активный день;
- recency: дней с последней активности / покупки;
- frequency: частота активности;
- тренд активности и GMV;
- отношение последних 30 дней к предыдущим 30 дням;
- отношение последних 7 дней к предыдущим 7 дням.

## Ключевые требования к решению

- Предсказать GMV для всех 250 000 пользователей.
- Не использовать данные после `2026-02-13` при построении финальных признаков.
- Финальный target относится к периоду `2026-02-14 — 2026-03-15`.
- Оптимизировать локальную **RMSLE**.
- Перед сохранением submission применять `predict = max(0, predict)`.
- Проверять отсутствие пропущенных и дублирующихся `user_id`.
