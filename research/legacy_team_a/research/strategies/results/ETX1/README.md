# ETX1 — гейт Sparse Event Transformer (`EXP-036`), фолд 2025-10-16, сид 42

Первый прогон `STRATEGY_13` в проекте. До него стратегия три недели стояла в
статусе NEW/Tier C: её собственные гейты (`STRATEGY_08` — личное время в
табличном виде, `STRATEGY_10` — сеть по дневной панели) должны были пройти
раньше. Гейт `08` дал **ноль** (`exp_021`), гейт `10` — **пройден** (`SEQ-01`
в смеси, LB 1.6501764). Отсюда и постановка: проверяется не полный ETX из
`research/strategy_NN_2.md`, а его **вариант B** — событийная токенизация с
календарным временем, без предобучения точечным процессом и без `ρ_i`.

## Что именно меняется относительно `SEQ`

| ось | `SEQ-01`/`SEQ-D3A` | `ETX-01` |
|---|---|---|
| представление | плотная сетка 365 дней, 70% ячеек пустые | только реальные события, ≤192 токена + query |
| «нет строки» | канал `present` = 0 | токена нет вовсе |
| время | позиция в сетке + `avail` + dow | `age`, `gap`, dow как признаки токена + ALiBi во внимании |
| модель | dilated TCN, 245 633 параметра | pre-LN трансформер, 1 115 433 параметра |
| глубина истории | канал `avail` | статик `depth` в query-токене |
| таргет, панель, фолды, метрика, оптимизатор, эпохи | — | **те же** |

## Почему именно так, а не по букве `strategy_NN_2.md`

* **Без предобучения точечным процессом (фаза 1).** Гейт обязан отвечать на
  вопрос «даёт ли событийное внимание сигнал», а предобучение — отдельная ось,
  которую нечем проверить: её главные заявки видны прежде всего на LB, а сабмиты
  кончились.
* **Без смещения в личном времени `τ_h · ρ_i`.** `exp_021` закрыл личное время
  как представление (30 признаков `pt_*` → −0.000006 wCV; контроль с ρ,
  перемешанной МЕЖДУ людьми, не хуже настоящей). Здесь стоит календарный аналог
  `−Δt/τ_h`, и он же дешёвый гейт для `G1`: если даже календарные `τ_h` не
  расходятся и не покупают ничего, личные не купят тем более.
* **Без multi-horizon/hazard голов** — `exp_024`, +0.00286 wCV, 0/4.
* **Без causal dense supervision.** Причинная маска её допускает, но панель на
  исторической позиции отбиралась бы не правилом организатора, а ближайший
  замер проекта (`exp_022`, плотная сетка cutoff'ов при равном объёме,
  +0.001263 wCV, 0/4) говорит, что лишние temporal-позиции сигнала не дают.
  Семантика супервизии: **один forward = один пример `(история ≤ T) → y30(T)`**.

## Инженерия, без которой гейт не помещался в 8 ГБ

1. **Событийная таблица целиком на GPU.** 30.6 млн событий × 14 каналов fp16 =
   0.86 ГБ лежат на устройстве; через PCIe едут только индексы `int32`. Иначе
   пришлось бы гнать плотное окно — 38 ГБ трафика на эпоху.
2. **Окно берётся двумя `searchsorted`** по глобально отсортированному ключу
   `user * 512 + day`. Никакого пер-примерного поиска: CPU на батч — два вызова.
3. **ALiBi без матрицы маски.** Для причинного внимания `−Δt_ij/τ_h` сводится к
   смещению, зависящему только от ключа (`+age_i/τ_h` сокращается в softmax),
   поэтому оно упаковано в лишнее измерение `q`/`k` (`head_dim` 15+1 = 16) и
   flash-ядро остаётся доступным. Матрица `(B,H,L,L)` стоила бы 67 МБ на слой.
4. **batch 512, не 1024.** При 1024 пик VRAM 7.29 ГБ на карте с 8 ГБ (из них
   ~2 ГБ занято рабочим столом) — шаг деградирует с 163 мс до 1946 мс, это
   вытеснение в системную память. Замеры: `bench`.
5. **`torch.compile` недоступен** — на Windows нет Triton. Прогон eager.
