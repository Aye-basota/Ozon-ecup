## 1. Протокол валидации (единый для всех экспериментов)

```
метрика      RMSLE = sqrt(mean (log1p(y) - log1p(max(0, pred)))^2)
             = обычный MSE по z = log1p(y)  ->  L2-регрессия на log1p(y)
               оптимизирует метрику точно, кастомный лосс не нужен

фолды S1     V in {2025-09-04, 2025-09-18, 2025-10-02, 2025-10-16}
train фолда  все cutoff'ы коридора с T + 30 <= V  (таргет обучения не заходит в валидацию)
коридор      2025-04-03 .. 2025-10-16, шаг 7 дней (29 cutoff'ов)
панель val   ВСЕГДА 3-блочная (правило организатора)
рядом с CV   bias = mean log1p(y) - mean z
```

Проверки корректности (`python -m src.smoke`, все проходят):

| проверка | результат |
|----------|-----------|
| `panel_users(2026-02-13, 3).height` | 250 000 — правило панели воспроизведено точно |
| состав панели vs `sample_submit` | совпадает полностью |
| `sample_submit == Σ gmv [2026-01-15..02-13]` | 100.0000% совпадений |
| `m_x` на тестовом cutoff'е | 2.2421 |
| leakage-тест: `build_features(T)` на полном и обрезанном по `T` датасете | побитово одинаково |
| 3-блочная панель на 2025-09-16 | n = 190 690, `m_y` = 2.6431, `P(y>0)` = 0.6106 |

**Оговорка о независимости фолдов.** Соседние фолды отстоят на 14 дней при 30-дневном
таргете, поэтому их целевые окна перекрываются примерно наполовину. «Улучшение на
4 фолдах из 4» означает согласованность, а не четыре независимых подтверждения.

### Что дало прирост

1. **Плотная сетка cutoff'ов (−0.0070).** Самый крупный и самый дешёвый по риску
   выигрыш: никаких новых признаков, только другое устройство обучающей выборки
   (0.63 млн → 5.0 млн строк). Ровно в предсказанном стратегией диапазоне.
2. **Нормировка длинных окон на доступную глубину истории (−0.0019 к E02, bias
   −0.095 → −0.055).** Измерено, что `all_*` **побитово совпадают** с `w365_*`
   на каждом обучающем cutoff'е (доступно 92..289 дней < 365, max|разница| = 0)
   и расходятся **только на тесте** (409 дней) — то есть в обучении они не несут
   никакой информации, а на тесте ведут себя иначе. Отсюда: `all_*`/`lifetime_*`
   выброшены, `w365_*` умножены на `365 / min(365, доступная история)`,
   `tenure`/`first_buy_age` заменены долями от доступной истории.
3. **Смесь трёх наборов признаков в лог-пространстве (−0.0017).** Корреляция
   остатков 0.992–0.996, поэтому выигрыш мал, но 10% усечённой модели
   (adversarial AUC 0.68 против 0.99) достаётся бесплатно как страховка.
4. **Якорная калибровка уровня (§5).** На локальных фолдах почти ничего не даёт,
   на тестовом горизонте — главный ожидаемый вклад.

## 4. Что не сработало

### 4.1 Переприменение правила панели на обучении — опровергнуто

Стратегия ожидала «высокий» эффект: разница уровня таргета между 3-блочной и
1-блочной панелью равна 0.198, значит модель «целится не туда».

Измерено: CV **хуже** на +0.00102, последовательно на 4 фолдах из 4; bias
практически не меняется (−0.1022 против −0.1064).

Причина: разница 0.198 — **маргинальная**, а не **условная**. 1-блочная панель —
надмножество 3-блочной, и различие состава уже закодировано в признаках (частота
покупок, recency, число активных дней). Условное `E[z | x]` от панели не зависит,
поэтому обучение на надмножестве просто даёт на 14% больше данных и выигрывает.

**Остаётся в силе:** панель **валидации** обязана быть 3-блочной, иначе метрика
считается по другой популяции.

### 4.2 Усечение истории до фиксированного `L` — слишком дорого

Механизм подтверждён полностью: adversarial AUC против теста падает с **0.9935/0.9912**
до **0.686/0.673** при `L = 180`, разброс между фолдами падает с 0.0131 до 0.0084,
bias — с −0.095 до −0.069. Драйверы разделения ровно те, что предсказаны:
`tenure`, `first_buy_age`, `w365_presence_rate`, `gap_mean`, `gap_max`, `trend_pres_90_365`.

Но цена оказалась вдвое выше обещанной (+0.0061 вместо +0.003…+0.006 — и это уже
на плотной сетке), а `L = 90` («минимум смещения», как предписывало правило выбора
из стратегии) — прямой провал: **+0.0305**. Правило «выбирать `L` по минимуму
смещения при AUC < 0.75» привело бы к худшей из проверенных конфигураций.

Разложение эффекта (2 последних фолда):

```
E02  полный uncapped набор                        1.74973
E04  uncapped минус 41 длинный признак           1.75705  (+0.00732)
E03a полное усечение до 180 дней                 1.75997  (+0.01024)
```

Длинные окна несут реальный сигнал (согласуется с `e08`: топ-признаки по gain —
`w180_days_buy`, `w180_orders`, `w90_days_buy`). Вывод: **лечить надо не окно,
а несопоставимость** — что и сделано в S1-E10.

### 4.3 Строгий коридор под `L` хуже широкого

Требование «полное окно `L` доступно на каждом cutoff'е» сокращает коридор с 29
cutoff'ов до 16 и стоит +0.0021. Данные снова важнее чистоты определения.

### 4.4 Нормировка не убирает adversarial AUC (побочный эффект)

У S1-E10 adversarial AUC против теста равен **1.0000** — хуже, чем у uncapped (0.9935).
Причина не в сдвиге распределения, а в **квантовании**: умножение на cutoff-специфичную
константу `365/avail` создаёт для каждого cutoff'а свою сетку значений, по которой
классификатор безошибочно узнаёт cutoff. Это отпечаток, а не сдвиг: диапазоны значений
как раз стали сопоставимыми, и на метрике E10 выигрывает, а bias падает вдвое.

Тем не менее это **непроверяемый локально риск**, поэтому в S1-BEST 10% веса отдано
усечённой модели с честным AUC 0.68, а уровень прогноза жёстко привязан к якорю.

### 4.5 Не проверено (сознательно отложено)

`L = 270`, обучение без фильтра панели (`train_blocks = 0`), веса cutoff'ов,
календарные признаки cutoff'а, двухчастная модель, CatBoost, шаг сетки 14 дней,
подбор числа раундов — прогоны сняты с очереди ради выпуска первой версии сабмита.
Это первые кандидаты на следующую итерацию (§7).

## 5. Калибровка уровня

### 5.1 Измеренные величины

`dm(T) = mean log1p(y_next30) − mean log1p(x_last30)` на **3-блочной** панели,
по всем 29 cutoff'ам коридора:

```
3-блочная панель:  mean +0.0251   median +0.0308   std 0.0480
1-блочная панель:  mean +0.0280   median +0.0341   std 0.0462
систематическая разница панелей:   −0.0029   (пренебрежимо мала)

YoY-аналог тестового окна (2025-02-13, 1-блочная):  dm = +0.1659
он же, приведённый к тестовой панели:               dm = +0.1630
```

`m_x` на тестовом cutoff'е известна **точно** из `sample_submit`: **2.2421**.

Отсюда четыре сценария целевого уровня `E[log1p(y_test)]`:

| сценарий | dm | целевой уровень |
|----------|-----|------------------|
| медианный дрейф коридора | +0.0308 | 2.2729 |
| средний дрейф коридора | +0.0251 | 2.2672 |
| **половина сезонной поправки (выбран)** | **+0.0969** | **2.3390** |
| YoY-аналог, полная сезонная поправка | +0.1630 | 2.4051 |

Уровень **самой модели** на тесте (обучение на всех 29 cutoff'ах):

```
S1-NORM (нормированные длинные окна)  2.4726
S1-UNC  (uncapped)                    2.4958
S1-CAP  (L = 180)                     2.5185
смесь 0.45 / 0.45 / 0.10              2.4876
```

**Модель перепрогнозирует при любом сценарии** — даже самый оптимистичный (YoY, 2.4051)
на 0.08 ниже её уровня. Знак поправки отрицателен независимо от сезонных допущений;
это самый устойчивый вывод раздела.

### 5.2 Выбор δ

```
δ = 2.3390 − 2.4876 = −0.1486
```

Целевой уровень взят как середина диапазона правдоподобия. Цена ошибки уровня `b`
при `σ ≈ 1.76` равна `sqrt(σ² + b²) − σ`:

```
b = 0.066 (промах до любого края диапазона при выборе середины)  ->  +0.0012
b = 0.132 (промах при ставке на один край)                       ->  +0.0049
```

То есть середина минимизирует худший случай. Две силы действуют навстречу друг другу
и обе не измеримы напрямую: сезонный подъём февраля–марта тянет уровень вверх
(наблюдался, но n = 1 год), а остаточное survivorship-смещение исторических панелей
тянет вниз (все 250k пользователей по построению дожили до ноября 2025 — февраля 2026,
поэтому исторические `dm` завышены на неизвестную величину).

### 5.3 Честная проверка процедуры на исторических фолдах

Бэктест якорной калибровки (`dm_hat` = медиана по **другим** cutoff'ам, leave-fold-out):

```
CV без калибровки         1.75988
CV с якорной калибровкой  1.76005   (+0.00017)
CV с оракульным сдвигом   1.75892   (недостижимая верхняя граница)
```

**Локально якорь не помогает** — забирает −18% оракульного выигрыша, то есть слегка
вредит. Причина: на фолдах разрыв train→val всего 35 дней, собственный bias модели
(−0.03…−0.09) сопоставим с ошибкой самой оценки `dm` (std 0.048), и калибровка
добавляет шум вместо сигнала.

**Это не аргумент против калибровки на тесте**, где разрыв 120 дней, а измеренный
перепрогноз 0.08–0.22 — в 2–4 раза больше локального. Зависимость квадратичная,
поэтому локальный CV принципиально недооценивает важность поправки. Но и уверенности
в её величине локальная проверка не даёт — это записано в риски (§7).

## 6. S1-BEST — итоговая конфигурация

```
данные        train.parquet, 10 информативных колонок из 18
панель обуч.  1-блочная («активен за последние 30 дней»)
панель валид. 3-блочная (правило организатора)
cutoff'ы      2025-04-03 .. 2025-10-16, шаг 7 дней, 29 штук, 6 065 972 строки
таргет        сумма gmv в (T, T+30], обучение на log1p(y), L2

признаки      три набора, усредняются В ЛОГ-ПРОСТРАНСТВЕ:
  0.45  S1-NORM  227 призн.  окна 7/14/30/60/90/180/365; w365_* нормированы на
                             365/min(365, доступная история); tenure/first_buy_age/
                             gap_max заменены долями; all_*/lifetime_* выброшены
  0.45  S1-UNC   236 призн.  тот же набор без нормировки
  0.10  S1-CAP   195 призн.  история усечена до 180 дней на каждом cutoff'е,
                             включая тестовый (страховка: adversarial AUC 0.68)

модель        LightGBM, objective=regression, 600 раундов
              lr 0.05, num_leaves 127, min_data_in_leaf 200, feature_fraction 0.7,
              bagging 0.8/freq 1, lambda_l2 5, max_bin 63, seed 42 (config.SEED)

постпроцесс   z = Σ w_i z_i;  z_cal = max(z − 0.1486, 0);  pred = expm1(z_cal)
              контроль: mean(log1p(pred)) = 2.3391 в якорном коридоре 2.28..2.41
```

**Сабмит:** `submissions/submission_strategy_1.csv`

Проверки пройдены: 250 000 строк, порядок `user_id` совпадает с `sample_submit`,
дубликатов нет, NaN/inf нет, отрицательных нет, min 0.000000, max 3 987.4,
нулевых предсказаний 0.243%, `mean log1p(pred)` = 2.3391.
Корреляция с baseline-персистентностью в лог-пространстве — 0.8135.

**Два дополнительных сабмита для калибровки CV↔LB** (та же модель, отличается только δ):

| файл | целевой уровень | δ | смысл |
|------|------------------|---|-------|
| `submission_strategy_1_level_low.csv` | 2.2803 | −0.2076 | нижний край: сезонности нет |
| `submission_strategy_1.csv` | 2.3391 | −0.1486 | **основной**: половина сезонной поправки |
| `submission_strategy_1_level_high.csv` | 2.4051 | −0.0825 | верхний край: YoY-сезонность повторится |

Разница LB-скоров этих трёх файлов **напрямую восстанавливает истинный уровень таргета**
(при фиксированной модели RMSLE как функция уровня — парабола с минимумом в истине).
Это единственный способ снять главную неопределённость Strategy 1, и он не требует
переобучения.

## 7. Риски и доверие к валидации

| риск | оценка | что сделано |
|------|--------|-------------|
| **Ошибка уровня на тесте** | **главный**. Перепрогноз 0.08…0.22 в зависимости от сезонного сценария; цена промаха на 0.13 — +0.005 RMSLE | δ выбран как середина диапазона; выпущены три сабмита по краям и центру для прямого замера |
| Сезонность 2026 ≠ 2025 | n = 1 год, структурная причина (23 февраля, 8 марта) правдоподобна, но не доказана | коэффициент 0.5 на сезонную поправку |
| Survivorship исторических панелей | локально **неизмерим**: в датасете нет «ушедших» пользователей | учтён как аргумент за нижнюю половину диапазона |
| Экстраполяция длинных признаков | adversarial AUC 0.9935 (uncapped) / 1.0000 (norm, но это квантование) / 0.686 (capped) | 10% веса усечённой модели + жёсткая привязка уровня |
| Перекрытие фолдов | целевые окна соседних фолдов пересекаются наполовину | CV std не считать оценкой независимой ошибки |
| LB-переобучение | public = 50k, σ ≈ 0.005–0.007 | не принимать решений по разнице < 0.01 на public |
| Разрыв train→test 120 дней | локально недостижим (максимум 35 дней на фолдах S1) | не измерен; кривая дрейфа снята с очереди — первый кандидат на следующую итерацию |

**Насколько можно доверять CV.** Относительные сравнения конфигураций надёжны:
протокол одинаков, панель валидации совпадает с тестовой, лукап исключён побитовым
тестом. Абсолютное значение 1.759 **не переносится на LB напрямую**: тестовая панель
шире (250k против 190k), горизонт дальше на 120 дней, а целевое окно — сезонный
максимум года. Ожидать на LB другое число — нормально; важна разница между сабмитами.

## 8. Воспроизведение

```bash
# 0. проверки корректности пайплайна
python -m src.smoke

# 1. кэш признаков (~2-8 c на cutoff)
python -m src.features --L 0   --min-history 90
python -m src.features --L 0   --min-history 90 --norm-long
python -m src.features --L 180 --min-history 90

# 2. baseline и ключевые эксперименты
python -m src.train --exp S1-B0   --L 0   --min-history 90 --train-blocks 1 --cutoffs recent3
python -m src.train --exp S1-E02  --L 0   --min-history 90 --train-blocks 1 --cutoffs all
python -m src.train --exp S1-E03a --L 180 --min-history 90 --train-blocks 1 --cutoffs all
python -m src.train --exp S1-E10  --L 0   --min-history 90 --train-blocks 1 --cutoffs all --norm-long

# 3. веса смеси по OOF
python -m src.blend --exps S1-E10 S1-E02 S1-E03a --step 0.05

# 4. уровень: сценарии и бэктест калибровки
python -m src.seasonal --skip-model
```
