# EXP076 — post-mortem EXP075 и strong-baseline validation channel

Статус: **аналитический post-mortem + новый validation channel**. Ни одна модель не
обучалась ради подбора коэффициентов, ни один scale не подбирался по leaderboard,
ни один сабмит не отправлялся. Public LB EXP075 использован ровно один раз — как
**одна noisy out-of-sample observation** в §D и §E, и *не* использован при
построении и настройке нового канала (§C) и при выборе направлений (§G).

Все числа пересчитаны из первичных артефактов. `EXP075/REPORT.md` и
`EXP075_CONFIRMATION/REPORT.md` не принимались на веру; там, где мои числа
расходятся с ними, расхождение названо явно.

---

## 0. Что оказалось не так — в одном абзаце

EXP075 нашёл **настоящий** сигнал: реализованный на public `rho = 0.017931`
отличается от нуля на **+4.93 sigma**. Но он был измерен относительно слабого RFM
baseline, который не содержит ни одной модели temporal-семейства, а разворачивался
поверх production-ансамбля, у которого такие модели есть. Против production-like
остатка тот же самый joint даёт `rho = 0.0130` (recency-weighted, min-projection)
и `0.0071` после проекции на historical ensemble span — то есть **в 2.8–5.3 раза
меньше**, чем показывал старый канал. Развёрнут он был при amplitude `1.0`, при
которой break-even равен `rho = 0.017648`; фактический `rho = 0.017931` выше
break-even всего на **1.6 %**, то есть на **+0.08 sigma**. Отсюда `ΔRMSLE =
-1.64e-05`: сигнал настоящий, улучшение — статистический ноль.

### A.2 Декодирование двух LB-значений

```text
R0 = 1.6461597403364463      (SUBMIT_ORTH_ALPHA)
R1 = 1.646143314225527       (SUBMIT_EXP075_JOINT_A1_365_A2)

actual Delta RMSLE   = -1.6426110919232073e-05
actual Delta MSE     = -5.4079735154033415e-05
MSE0 = 2.7098418907045563    MSE1 = 2.7097878109694022
```

Так как `d` ортогональна всему submission-span, а `z_alpha` лежит внутри него,
`mean(d * r_alpha) = mean(d * target_log)`; baseline входит только через `sigma_r`.
Из `Delta MSE = -2*mean(d*r) + mean(d^2)`:

```text
implied public residual alignment  mean(d*r) = 0.0017150146011944898
implied rho                                  = 0.017930726124852213
implied optimal amplitude a*                 = 0.5080095593371436
   (проверено независимо сеткой из 150 001 точки: argmin = 0.508010)
break-even rho (при amplitude 1.0)           = 0.017648020391829257
```

**Гипотеза «realised rho ≈ 0.018» подтверждена независимо: 0.017931.**
Единственная неопределённость самого декодирования — состав public-подвыборки в
`RMS(d)`; по 300 случайным 50k-подвыборкам фактической `d` 95 %-полоса даёт
`rho ∈ [0.017723, 0.018112]`, `a* ∈ [0.5078, 0.5082]`. Влияние ненулевого
`mean(d)` при `|mean(r)| <= 0.05` не превышает `1.3e-04` по rho. То есть точка
измерена практически точно; вся неопределённость — в переносе на private.

### A.4 Значимость (public = 20 % = 50 000 пользователей, DISCRIPTION.md стр. 113)

SE получен не по гауссовой формуле, а эмпирически: 400 случайных подвыборок по
50 000 строк из реальных пар `(u_perp, r_strong)` фолда 2025-10-16 (197 379 строк),
с конечно-популяционной поправкой на `f = 50k/250k`.

```text
kappa = E[u^2 r^2] / (E[u^2] E[r^2])            = 0.90593      (хвосты НЕ утяжеляют)
SE(rho) при n=50k, эмпирическая                 = 0.0036378
SE(rho_pub - rho_full)                          = 0.0038072
```

| гипотеза | z | вывод |
| --- | ---: | --- |
| `rho = 0` | **+4.93** | сигнал реален (одностор. p ≈ 4e-07) |
| `rho = break-even` (т.е. `Delta MSE = 0`) | **+0.078** | улучшение **незначимо** (p ≈ 0.47) |
| `rho = 0.037940` (старый headline) | **−5.50** | старый канал опровергнут |
| `rho = 0.029942` (старый stress-span) | **−3.30** | старый канал опровергнут и в консервативном чтении |

**Ответ на главный вопрос §1.** EXP075 нашёл настоящий signal и переоценил его
amplitude ровно вдвое (`a* = 0.508`). Public improvement при этом *полностью*
совместим с шумом: `Delta MSE` отличается от нуля на 0.08 sigma. Оба утверждения
верны одновременно, и это не противоречие: значимость `rho > 0` и значимость
`rho > break-even` — разные тесты, и второй провален.

```text
actual Delta RMSLE   = -0.000016426110919
actual Delta MSE     = -0.000054079735154
implied rho          =  0.017930726124852   (+4.93 sigma vs 0; +0.08 sigma vs break-even)
significance         =  улучшение НЕ значимо; направление значимо
implied optimal amp  =  0.508009559337144
```

## B. Why validation overpredicted

### B.1 Что было построено

Использована библиотека canonical OOF с полным provenance
(`registry/models.csv`, `artifacts/manifests/prediction_sources.csv`): **40**
диверсифицированных прогнозов, все 770 616 строк, покрытие 4/4 фолда, ключ
`(cutoff, user_id)`, порядок строк совпадает с
`EXP075/clean_forward_predictions.parquet` **строка в строку** (проверено).
Семейства: lightgbm direct / distribution head / two-part, dilated TCN (`SEQ`),
event transformer (`ETX`), personal-time, ridge, holiday-YoY, multi-horizon
hazard, gap-axis, tabular refresh, BG/NBD, conditional-fresh MoE.

Три baseline-лестницы, все out-of-sample по строкам и forward по времени
(веса стека — только по строго более ранним фолдам; фолд 1 — замороженный
production-рецепт без подгонки):

| baseline | wCV (1:2:4:8) | что это |
| --- | ---: | --- |
| weak RFM (EXP075) | 1.755492 | то, против чего мерил EXP075 |
| `EXP037 STRONGEST_CURRENT` frozen | 1.748229 | боевой рецепт 0.10 CAP + 0.20 UNC + 0.25 DIST + 0.225 ETX-AVG3 + 0.225 SEQ-AVG3 |
| forward ridge stack по 40 компонентам | 1.747538 | сильнейший воспроизводимый |
| **composition-matched к `SUBMIT_ORTH_ALPHA`** | 1.749517 | см. B.2 |

### B.2 Состав реального production-сабмита, измеренный, а не предположенный

`z_alpha = log1p(SUBMIT_ORTH_ALPHA.predict)` регрессирован на TEST-предсказания
компонент (`ztest_*.npy` + BTYD). Контроль метода: тот же регресс на
`EXP037 z_strongest` восстанавливает документированный рецепт **точно** —
`R^2 = 1.000000`, доли `SEQ 0.2250 / ETX 0.2250 / TAB 0.5499`.

```text
SUBMIT_ORTH_ALPHA   R^2 = 0.997317
   SEQ  0.1283      ETX 0.1962      TAB 0.6874      BTYD -0.0119
   необъяснённый остаток RMS 0.0840 против centered RMS 1.6224 (5.2 %)
```

То есть в развёрнутом baseline доля sequence-семейства **32.5 %** против 45 % у
EXP037. Это существенно, потому что именно sequence-семейство поглощает сигнал
A1/A2 (B.3). Composition-matched historical baseline построен как forward-fit
подстеки по семействам, смешанные ровно в этих долях, с калибровкой уровня по
строго более ранним фолдам.

### B.3 Механизм A — weak historical baseline problem (доминирующий)

Тот же frozen joint `D = 0.7462560853*A1_365 + 0.6466415685*A2`, min-projection,
против остатка baseline, в который добавлено только указанное семейство
(веса стека — по строго более ранним фолдам):

| baseline | fold RMSLE 10-16 | joint rho 10-16 | rho wavg | доля сигнала съедена |
| --- | ---: | ---: | ---: | ---: |
| только weak RFM | 1.747355 | 0.035027 | 0.037821 | — |
| + tabular family (23 модели) | 1.742233 | 0.018104 | 0.020130 | **47 %** |
| + sequence family (16 моделей) | 1.741082 | 0.008487 | 0.011318 | **70 %** |
| + всё (39) | 1.741099 | 0.006015 | 0.009254 | 76 % |

Sequence-семейство даёт почти весь прирост точности и **одно** съедает 70 %
сигнала: A1/A2 переоткрывают представление, которое `SEQ-AVG3` (dilated TCN по
тому же 11-канальному панельному представлению) и `ETX-AVG3` (event transformer)
уже несут в боевом ансамбле. Заметьте: переход `EXP037 -> forward stack` улучшает
RMSLE всего на 0.00055, но роняет rho c 0.012018 до 0.006913. **Распад rho
управляется представленческим перекрытием с baseline, а не точностью baseline.**

### B.4 Механизм B — projection mismatch (реальный, но вторичный)

TEST-span восстановлен точно: 78 векторов (67 canonical `Z.npz` + 11 локальных
submission), centered rank **67**, воспроизведённая `D_perp` совпадает с
сохранённой с `max abs = 7.41e-08` (= разрешение float32). То есть проекция
воспроизведена, а не смоделирована.

Два измерения, которых не было в аудите:

1. **Проекция убирает не инкумбента, а модельное разнообразие.** Проекция
   `D_raw` только на `{1, z_alpha}` убирает **0.26 %** центрированной энергии;
   полный span убирает **32.3 %**. Вложенный sweep: 12 векторов — 2.0 %,
   20 — 13.9 %, 45 — 24.2 %, 67 — 29.6 %, 78 — 32.3 %.
2. **Submission-span уже содержит всё пространство компонент.** Для каждой
   боевой компоненты доля её TEST-предсказания *вне* span:

   | компонента | вне span | | компонента | вне span |
   | --- | ---: | --- | --- | ---: |
   | `BTYD:z_strongest` (=EXP037) | 1.4e-07 | | `ETX-01-S42-DCW` | 8.6e-04 |
   | `S1-DIST` | 4.9e-07 | | `SEQ-C289-S43` | 1.5e-03 |
   | `S1-UNC` | 1.2e-05 | | `SEQ-D3A-BASE-S42` | 4.1e-03 |
   | `S1-CAP` | 1.4e-04 | | `L90_norm0_tb1` (худший) | 1.8e-02 |

   Значит исторический span из 40 OOF-компонент — **добросовестный, скорее даже
   консервативный аналог** реального TEST-span, а не его завышение.

Что именно удаляется — и было ли оно предсказательным (фолд 2025-10-16, joint):

```text
против weak RFM :  corr(D_removed, r) = 0.060266     corr(D_perp, r) = 0.005720
против strong   :  corr(D_removed, r) = 0.002471     corr(D_perp, r) = 0.004970
```

**91 % корреляции joint со слабым остатком живёт ровно в той части, которую
production-span удаляет.** Против сильного baseline удаляемая часть уже почти
непредсказательна — потому что её содержание и есть то, что ансамбль уже знает.
Это тот же механизм A, увиденный со стороны геометрии.

Пересчитано из `EXP075_CONFIRMATION/fold_*.parquet` напрямую (мои числа
совпадают с аудитом до последнего знака: `rho 10-16 = 0.035587`, active-only
`0.036896`):

| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 2025-10-16 | 197 379 | 2.000 % | 1.748825 | 0.035587 | 0.036896 (+3.7 %) | 0.3871 | 0.061994 | 0.017725 |
| 2025-10-30 | 201 074 | 1.362 % | 1.745881 | 0.037383 | 0.037763 (+1.0 %) | 0.3828 | 0.079755 | 0.022840 |

| 2025-12-11 | 215 823 | 0.553 % | 1.761137 | 0.040618 | 0.040737 (+0.3 %) | 0.3862 | 0.075128 | 0.021329 |
| 2026-01-14 | 233 152 | 0.000 % | 1.706516 | 0.036223 | 0.036223 (+0.0 %) | 0.4381 | 0.081247 | 0.023805 |

* **survivorship — не объяснение**: ограничение на target-active меняет rho не
  более чем на +3.7 % и ровно на самом чистом фолде; на «грязных» поздних фолдах
  эффект +0.0…+1.0 %.
* **третий, ранее не названный механизм — инфляция амплитуды вне режима.**
  `RMS(u_raw)` замороженной модели растёт с 0.0620 до 0.0812 (+31 %) при
  переходе в поздний режим, а rho — нет. Break-even (`RMS(u)/2 sigma_r`) при этом
  уезжает с 0.0177 до 0.0238. На TEST `RMS(D_raw) = 0.073178` (break-even
  0.022228) — ровно поздне-режимный уровень. Только проекция вернула норму к
  0.058103 и break-even к 0.017648. **Без span-проекции сабмит был бы заведомо
  хуже инкумбента**, и это не случайная удача, а единственная причина, по которой
  результат вышел нулевым, а не отрицательным.
* **чистые vs искажённые улики.** Чистые: 4 фолда до 2025-10-16 включительно
  (target-окно целиком вне организаторского eligibility-конуса). Искажённые:
  2025-10-30 … 2026-01-14 — их target-окна пересекаются с блоками, по которым
  отобраны 250 000 пользователей; на 2026-01-14 target-окно *и есть* блок 0.
  Именно на них старый канал брал свои самые высокие rho (0.0454), и именно они
  использовать как доказательство generalization нельзя. В §C и §D новый канал
  строится **только** на чистых фолдах; поздние фолды используются исключительно
  как оценка режимного дрейфа.
* **найдена реальная утечка в библиотеке артефактов.** В `oof_BLOCK4_SAF.npz`
  поле `activity` **тождественно** `1[target_events > 0]` на фолде (совпадение
  100.0 %). Как «направление» оно даёт post-projection `rho = 0.086`. Исключено.
  Любой headroom-скан по этой библиотеке обязан его выбрасывать.

## C. Strong-baseline validation channel (SBVC)

### C.1 Определение канала

1. **Strict forward time.** Только 4 чистых фолда `2025-09-04 / 09-18 / 10-02 /
   10-16`; `2025-10-16` — последний cutoff, у которого 30-дневное target-окно
   целиком вне организаторского eligibility-конуса.
2. **No target leakage.** Все входы — либо перестроенные из raw, либо canonical
   OOF с provenance; `oof_BLOCK4_SAF['activity']` исключено как метка (§B.5);
   contaminated teammate OOF (occurrence-компоненты `latest`) не использованы —
   у них вообще нет canonical OOF.
3. **Baseline out-of-sample по каждой строке.** Компоненты — OOF по построению;
   веса стека берутся **только** со строго более ранних фолдов; на первом фолде
   используется замороженный документированный production-рецепт (никакой
   подгонки на этом фолде).
4. **Baseline воспроизводит diversity боевого ансамбля.** Не «сильнейший, какой
   получится», а **composition-matched**: доли семейств взяты из регрессии
   реального `SUBMIT_ORTH_ALPHA` на TEST-предсказания компонент (`R^2 = 0.9973`,
   метод верифицирован точным восстановлением рецепта EXP037).
5. **Кандидат оценивается только на остатке этого baseline.**
6. **Кандидат сначала проецируется вне historical ensemble span** (константа +
   baseline + все 40 компонент) — исторический аналог того, что реально сделано
   с `D_perp` на TEST (§B.4 показывает, что этот аналог не завышен).
7. **Amplitude фитится только на более ранних фолдах**, оценка — на следующем.

Ключевое отличие от старого канала — не «более сильный baseline», а то, что
baseline **того же представленческого состава**, что и боевой сабмит.

## E. EXP075 decision

### E.1 Posterior для истинной full-test / private амплитуды

Prior — **только** historical strong-baseline evidence (§C), без LB.
Likelihood — одна public-обсервация с эмпирическим SE из §A.4.
Нормальная сопряжённая модель, prior sd `tau = 0.006` (покрывает разброс между
post-proj и min-proj вариантами и межфолдовую дисперсию 0.0023).

| prior | prior mu | posterior mu (rho) | posterior sd | **posterior optimal amplitude** | prior-only optimum |
| --- | ---: | ---: | ---: | ---: | ---: |
| SBVC post-projection | 0.007092 | 0.014819 | 0.003215 | **0.420 ± 0.091** | 0.201 |
| SBVC min-projection | 0.013398 | 0.016630 | 0.003215 | **0.471 ± 0.091** | 0.380 |
| (tau = 0.004, post-proj) | 0.007092 | 0.012779 | 0.002758 | 0.362 ± 0.078 | 0.201 |
| (tau = 0.004, min-proj) | 0.013398 | 0.015776 | 0.002758 | 0.447 ± 0.078 | 0.380 |

**Насколько expected-private optimum отличается от public optimum:** public

амплитуде).

### E.2 Достаточно ли уверенности, чтобы вообще делать shrinkage

```text
P(rho > break-even) при amplitude 1.00 : 0.189 (post-proj prior) … 0.376 (min-proj prior)
P(rho > break-even) при amplitude a*   : 0.989 … 0.995
E[Delta RMSLE] при amplitude 1.00      : +0.000164 … +0.000059   (то есть ОЖИДАЕМО ХУЖЕ инкумбента)
E[Delta RMSLE] при amplitude a*        : -0.000181 … -0.000228
E[Delta RMSLE] при prior-only amplitude: -0.000132 … -0.000219
```

Решающее наблюдение: **shrinkage обосновывается без leaderboard.** Даже если
public-обсервацию выбросить целиком, prior-only оптимум равен `0.20–0.38`, а
ожидаемый выигрыш от него `−0.00013…−0.00022`. LB-точка не создаёт этот вывод,
она лишь сдвигает оптимум с `0.20–0.38` на `0.36–0.47`. Поэтому это не
leaderboard chasing: величина берётся из posterior, а не из public-оптимума
`0.508`, и рекомендуемое значение **сознательно ниже** public-оптимума.

### E.3 Вердикт

```text
SHRINK_WITH_EVIDENCE
```

Обоснование и конкретика:

* **Не выбирать `SUBMIT_EXP075_JOINT_A1_365_A2.csv` как финальный private-сабмит.**

* Ожидаемая величина выигрыша (`0.0002`) — **13 % оставшегося разрыва**. Это

## F. Remaining gap

Пересчёт от фактического нового best, ORTH-`rho` **не** добавляется повторно —
`SUBMIT_ORTH_ALPHA` и есть baseline, его сигнал уже внутри 1.6461597.

from   1.646143314225527       MSE = 2.7097878109694022
to     1.6446514942            MSE = 2.7048785373742925

required Delta RMSLE = -0.0014918200255272
required Delta MSE   = -0.0049092735951097
required new independent rho (при оптимальной амплитуде) = 0.0425638570155155
```

Для сравнения масштабов:

| объект | rho против production-остатка |
| --- | ---: |
| **нужно** | **0.042564** |
| реализованный EXP075 joint (факт, public) | 0.017931 |
| EXP075 joint по SBVC (интервал) | 0.0071 – 0.0134 |
| потолок всех дешёвых направлений, held-out (§G.0) | 0.014980 |

То есть требуется независимое направление, **в 2.4 раза сильнее всего того, что

```

Весь оставшийся разрыв численно равен смещению общего уровня прогноза на
**0.070** — величине *меньшей*, чем типичный межфолдовый дрейф уровня (§G.2).

  усадку `lambda <= 0.5` и только один раз.
* **Expected compute.** 10–20 минут CPU, ноль обучений (всё считается из
  `seq_gmv_v1.npy` и уже готовых fold-парктов).
* **Известное препятствие, названное честно.** Наивный YoY-перенос даёт
  прогноз уровня TEST-окна `2.418` против `2.3299` у сабмита, то есть «ошибку»
  `+0.088` и мнимый выигрыш `−0.0024 RMSLE`. **Этому числу верить нельзя**:
  панельный уровень монотонно растёт весь 2025 год (`1.514 → 2.513`), и этот рост
  неотделим от survivorship-набора (250 000 пользователей отобраны по активности
  в трёх блоках ноябрь-2025 … февраль-2026, поэтому окно `2026-01-15…02-13` —
  это в точности организаторский блок 0 и оно обусловлено активностью на 100 %,
  а окно `2025-01-15…02-13` не обусловлено ничем).
  > **Missing artifact:** второй год панельной истории **или** контрольная
  > когорта без eligibility-отбора.
  > **Что блокирует:** разделение survivorship-рампы и календарной сезонности,
  > то есть безусловную офлайн-оценку абсолютного уровня TEST-окна. Без него
  > допустима только *относительная*, усаженная поправка по правилу выше, и
  > именно поэтому `lambda <= 0.5` и однократность — часть гейта, а не деталь.

### G.3 Что делать не надо

* Переобучать A1/A2 на свежих cutoff'ах — закрыто пилотом G.0a.
* Искать новые temporal-представления — held-out потолок 0.0047 (G.0).
* Продолжать residual-поиск по имеющимся признакам — потолок 0.0150 против
  требуемых 0.0426 (G.0, §F); согласуется с `exp_053`.
* Подбирать amplitude EXP075 по public — 1 sigma амплитуды равна 0.108, различить
  0.40 и 0.508 на public невозможно (§E.3).

## Приложение: артефакты и воспроизводимость

Код в `code/`, результаты в `out/`. Порядок запуска:
`s1` (декод LB) → `s3` (сборка матрицы компонент) → `s4` (лестница baseline) →
`s5` (rho по baseline × проекциям) → `s6a/s6b` (перестройка TEST-span и доля
компонент внутри него) → `s7` (значимость) → `s8` (sweep по span) →
`s9` (аблация семейств) → `s10` (состав `ORTH_ALPHA`) → `s11` (composition-matched
baseline) → `s12` (таблица SBVC) → `s13` (режим) → `s14/s16` (headroom и потолок)
→ `s17/s17b` (пилот устаревания) → `s18` (prediction test и posterior) →
`s19` (независимая перепроверка) → `s20/s21/s22` (ось уровня).

`OZON-E-CUP/data/processed/seq_{panel,gmv,uid}_v1.npy`,

`target_y30` из mmap против фолд-паркета (`9.1e-13`), восстановление рецепта
